# INTEG-01：DATA → PAPER → TTS 集成验收

基线为 `8761d4ba25c481d59d72e378a285395f448c5eb2`。测试使用 PostgreSQL 16 隔离 schema、临时图片／预览／音频目录、真实 XLSX 和测试专用评分插件及合成器；不连接生产数据或付费服务。跨模块测试见 [test_integ_01.py](../backend/tests/test_integ_01.py)。

| 阶段 | 测试输入与持久化身份 | 验证结果 |
|---|---|---|
| 教师导入 | 15 列 XLSX 含 `0001` 选择题、`0002` 对话题和 `0003` 问答题；H/I/J/K 嵌入不同图片 | HTTP 预览、应用重建后恢复、固定操作 ID 重试及导入成功；`bank_id`、`task_id`、`task_revision_id`、`batch_id` 分别持久化；另一题库相同题号身份独立 |
| 修订与组卷 | 选择题 M/N/O、对话完整 F、E 可选引导语及独立 D 排序 | 读取修订和图片核对字段与槽位；添加、替换、重排后的 `PaperEntry` 固定精确修订，题序不修改 D |
| 发布 | 测试插件及测试评价合同、显式测试语音配置 | 事务固定 `PaperEntry`、非空 `EvaluationPlan`、E/F 固定语音请求；未准备音频时不就绪 |
| 固定音频 | 独立 Worker 路径与确定性测试合成器，输出有效 WAV | 生成的来源仅为 E/F，教师鉴权后试听；文件摘要与数据库一致，完整时就绪 |
| 后续演进 | 同题连续导入 v2、v3，更新 M/N/O | 旧试卷仍指向 v1，原评价需求和音频来源不变；复制草稿保留修订、插件与配置，主动替换后才使用 v3；直接 SQL 不能修改冻结事实 |
| 冲突与恢复 | 预览过期、草稿编辑与发布竞争、两个数据库引擎竞争一个音频 | 过期提交被拒；并发编辑与发布只有一个成功且无半冻结；同一音频仅一个合成调用 |
| 中断与损坏 | 模拟外呼中断，或文件已保存但数据库绑定中断；重新创建数据库引擎 | 不确定请求在未授权前不再调用，显式确认后才重试；SAVED 结果无需再次合成即可绑定；损坏／缺失文件不能试听或通过就绪检查 |

上述 UUID 在每次测试中动态生成；测试通过数据库关联和 HTTP 返回值核对它们，不使用预设的生产身份。模拟中断使用受控异常并重建 Engine，未执行操作系统级强制杀进程测试。音频准备接口的 202 只是提示等待独立 Worker 扫描，不证明已开始合成或已立即排队。

本轮未发现需要修改的生产逻辑。现有 [DashScope 适配器测试](../backend/tests/test_tts_worker.py) 使用模拟 SDK 验证参数、错误及 WAV 格式，不证明真实账号权限、模型／音色可用性、服务端语速效果或真实供应商响应。后续若需真实冒烟，必须由操作人员在私有环境配置 `DASHSCOPE_API_KEY`、显式选择已批准的模型和音色并主动启动 Worker；该操作可能收费，默认测试和 CI 均不执行。

**Session 开发判断：**本次证据支持进入 Session 基础开发；创建 Session 时仍须在数据库事务内锁定试卷并重新核验发布状态与音频就绪，不能把本次静态检查当作并发授权。生产施测还依赖真实供应商冒烟、正式评分插件、Session 鉴权及相应功能验收。
