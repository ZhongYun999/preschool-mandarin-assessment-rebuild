# VNext｜试卷组卷、发布、整卷复制与代码评分插件专项设计 P1.1

> 日期：2026-11-12。状态：方案草案；已确认/待确认分开标注。本稿修订 P1.0 关于「复制旧试卷时升级题目版本」「网页在线编排新评分算法」「评分说明仅是教师参考文字」的错误理解；保留此前确定的试卷发布冻结、归档及无凭据不得结算等原则。本稿不修改线上数据或仓库。

## 0. 四条已确认的最高原则

1. **从题库选题**：教师只看到所选题库中同一 `task_code` 的最新、未归档 `TaskRevision`；教师不操作隐藏版本号。可添加、移除、整体替换和拖拽排序；组卷过程中绝不编辑题目内容。
2. **整份复制试卷**：复制的是原卷实际内容，含旧题目修订、题序、评分算法身份和适用的已冻结配套信息。复制成独立新草稿，不自动检查、升级或替换为题库最新版本；即使原题已归档也可保留。教师后来主动替换某个模块时，才按普通选题规则选择当前最新版本。
3. **评分算法是已部署的代码插件**：由开发者根据教师的新要求实现、测试、随服务器正常发布；教师只在组卷时选已注册的插件。**无在线编辑公式、动态 Python 代码、运行时热加载、参数配置面板的需求。**
4. **底层评测与上层换算分离**：题型 Handler/评测适配层生成并保存真实原始评分证据；评分插件只消费这些证据，计算单题有效分、题型汇总、整卷总分、档位等，不操纵录音、轮次、ASR、LLM/TTS 工作流，也不能伪造缺失的底层评价结果。

## 1. 旧版实际评分模式（参考证据，不自动继承业务限制）

旧仓库 `domain/scoring_scheme.py`、`domain/trial_scoring.py`、`services/score_resolution_service.py`、`services/summary_service.py`、`domain/assessment_rating.py` 支持以下两套历史方案：

### 1.1 `legacy_v1`

- 根据已确认的各题有效分，按题型平均与权重汇总；中、大班可包含额外 `mandarin_norm` 综合观察项。
- 旧配置（不等于 VNext 全局要求）：小班指令 30%／跟读 30%／问答 40%；中班指令 20%／跟读 30%／问答 40% 与规范观察 10%；大班跟读 20%／对话 30%／说话 30% 与规范观察 10%。
- 历史分数来源解析曾依据正式分、最终分、模型分等优先级选择，并在特定路径做截断。新插件可以借鉴，但不能把历史优先级作为全系统的底层事实定义。

### 1.2 `trial_2026_v1`

- 原方案的十题结构、按学段指定题型数量是**该历史算法的前提**，不是所有新试卷都应遵守的限制。
- 小班题型权重：指令 30%、跟读 30%、问答 20%、对话 20%；中班：指令 20%、跟读 30%、对话 25%、说话 25%；大班：指令 20%、跟读 20%、对话 30%、说话 30%。
- 跟读三题以 30%／30%／40% 汇总；正式必要有效分缺失时总分为 `None`，不可当作真正的 0 分；不额外计入 `mandarin_norm`。
- 总分基于 5 分制、可换算百分制；评级旧阈值依次为 4.5 优秀、4.0 良好、3.0 合格，其余不合格。

**迁移注意**：若移植为 VNext 插件，必须明确是否追求旧算法行为兼容。如果修正了历史异常处理或分数来源逻辑，应使用新的插件版本，不假称输出与旧版完全等价。

## 2. 核心实体与两种选题来源

```text
TaskBank
  └─ TaskIdentity(bank_id + task_code, latest_revision_id, archived_at)
       ├─ TaskRevision v1  [不可变]
       ├─ TaskRevision v2  [不可变]
       └─ TaskRevision v3  [不可变]

RegisteredScoringPlugin(plugin_id, implementation_version, availability)
   └─ server-deployed immutable behavior [旧版可继续运行]

Paper [DRAFT | PUBLISHED | ARCHIVED]
  ├─ PaperEntry(position, task_revision_id, origin)
  │    origin: SELECTED_FROM_BANK | COPIED_FROM_PAPER
  └─ scoring_plugin_id + implementation_version

Session(published_paper_id)
  └─ SessionTask(PaperEntry) → Attempt → Submission → RawEvaluation → ScoreResult
```

`origin` 是为了说明来源语义而设的逻辑属性，不要求一定持久化为新的数据库枚举。关键是 **复制保留确切 `task_revision_id`，新选题只从最新修订中创建条目**。同一张草稿可以同时包含复制保留的历史条目与后来主动替换进入的最新条目；不必把它们强行全部升级。

`PaperStandard` 若存在，是可选的组卷模板/教学规范，不与 `RegisteredScoringPlugin` 混在一起；插件仅在确有算法输入前提时验证自身要求。

## 3. 新建组卷与草稿编辑【已确认】

1. 选择题库、试卷基本信息、已经部署且可选的评分插件。
2. 题库候选界面仅展示该 `TaskIdentity` 的**最新且未归档**修订；题库 D 列排序号用于候选展示排序，不代表发布后的试卷题序。
3. 教师选择整个题目模块加入试卷，或进行整题替换、移除、插入、拖拽排序；题目文本、图片、评分说明、Dialogue 轮数等只能返回 Excel 题库修订流程修改。
4. 普通新建草稿在首次选入时选当前最新修订；草稿期间如果对应题目发布了新修订，是否进行**明确提示并由教师重新选入**，或在正式发布前做当前最新核验，可作为组卷 UX 细化。**但不可把“复制旧卷”自动升级作为该规则的推论。**
5. 发布前展示将冻结的具体题目、题序、评分插件身份；发布事务原子固定这些事实。已发布 PaperEntry 不追查题库最新修订，也不因题目归档失效。

### 3.1 冻结语义的关键约束

- 已发布内容不可原地修改；已运行的 Session/Submission/ScoreResult 必须始终能解析相同 PaperEntry 的内容及其评分算法。
- 如果草稿含来自旧卷的历史修订，它们仍是有效草稿条目；**发布校验不能以“不等于题库最新”或“题目已归档”为由拒绝这类明确复制的条目**。
- 对尚未有发布事实的普通新增/替换条目，才执行最新、可选候选规则。
- 拖拽只更改草稿的 `PaperEntry.position`，不修改题库排序 D，也不创建题目新版本。

### 3.2 发布时固定 TTS 的字段消费【已确认；重新生成属实现建议】

- 固定语音仅使用冻结 TaskRevision 的 **E 测试员引导语**（`guide`）与 **F 题目内容**（`prompt`）。E 可以为空，留空不生成对应语音；F 提供正式题目播报。选择题正确选项或其他题型参考文本统一来自 **M 参考答案**，**不得被固定 TTS 读取或朗读**。
- 发布操作可异步准备上述语音，必要音频就绪后试卷才供正常新建 Session 使用；生成和播放必须保留字段语义，不从 N 评分说明、M 参考答案或题型显示名称推断文本。
- Dialogue 的初始题目音频播放**完整 F**，不按标点截取首问；Speaking/Dialogue 后续生成的动态问题属于运行时 TTS，不属于发布固定 E/F 音频。
- 可提供已发布试卷固定语音的手动重新生成入口，始终用该卷冻结的 E/F 原文和明确的语音配置；**已被 Session 引用的音频资源不可被原地覆盖**。具体界面和无 Session 时是否允许直接替换发布资源属于实施细节，不新增复杂业务流程。

## 4. 复制旧试卷：原样继承的完整定义【本次修正，已确认】

| 原卷事实 | 新草稿复制行为 |
|---|---|
| 题目 `TaskRevision` | 保留同一不可变修订版本，不查询最新 |
| 每题题型、题干、Dialogue 轮数、图片及题目级评分提示词 | 通过相同修订身份原样保持 |
| 题目排列顺序 | 原样保持，可在新草稿拖拽调整 |
| 评分插件 | 保持同一 `plugin_id + implementation_version`，不自动升级 |
| 试卷名称、说明和新 ID | 新建独立草稿，可允许教师按草稿操作修改 |
| 旧卷 Session / Submission / ScoreResult | **绝不复制**；新试卷没有历史作答或成绩 |
| 发布前派生的 TTS 等资源 | 可复用内容相同且技术兼容的现有素材，或重新准备；不构成题目版本升级 |

**实例**：旧卷 D001 固定 v2，题库现在 v5 或 D001 已归档。复制后的新草稿仍持有 v2；编辑题序不触碰 v2。如果教师主动移除 D001，再从题库选 D001，只能选当前最新且未归档的修订（如已归档则须先恢复题库候选资格或改选其他题）。

如果某旧评分实现已无法执行，应明确报告**技术不可用**并阻止无法成立的评分交接，不能偷偷改为新插件。应优先保障历史已发布卷的评分实现长期可用。

## 5. 试卷状态与归档、删除

- `DRAFT`：可编排题目、调整顺序、选用已部署算法、修改试卷自身名称或说明；不能编辑 TaskRevision 的题目内容。可发布，未被业务引用时可删除。
- `PUBLISHED`：固定内容和算法，可创建新的测评 Session，支持归档和完整复制；不能原地编辑已发布事实。
- `ARCHIVED`：不进入小程序新测评的选卷列表，不新建普通 Session；已存在 Session 不受影响；可复制为新草稿，且复制来源的历史修订有效。
- 题目归档只影响新从题库选题，不影响旧试卷及其复制结果。技术资源准备失败属于操作错误，不必强行新增公开业务状态。

### 5.1 删除与撤销【仍待确认】

- 未引用的草稿：允许删除。
- 已发布但从未被任何 Session 或其他权威业务事实引用：**建议**允许物理删除，删除时事务内重新核查引用；不是把它原地退回草稿重写。
- 被已发布 PaperEntry 等事实引用的任何题目版本：不能物理删除破坏引用，允许归档；全历史版本都没有有效外部引用的题目身份才可考虑物理删除。
- 已存在 Session 的试卷不可物理删除。归档不影响在途 Session、成绩、历史查询。

## 6. 底层评测协议：统一交接结构，而非强迫统一数值范围【已确认原则，接口细节建议】

**不是所有评价引擎都会返回一个同量纲的单一数字**。统一的是 `RawEvaluation` 的证据封装和读取方式，而非把所有 LLM／ISE／选择题结果先硬转换成 0～5 分。

```text
RawEvaluation
  submission_id / attempt_id / task_type
  evaluator_kind          # image_choice / ISE / LLM / other
  provider_and_model      # 哪个供应方、模型、引擎（如适用）
  evaluator_contract_ver  # 产生原始评价的调用协议版本
  status                  # SUCCESS | UNAVAILABLE | FAILED 等技术语义
  metrics                 # 结构化数值/等级/维度分及原始量纲
  original_result_ref     # 原始响应或证据引用（依法合规保存）
  prompt_revision_ref     # 如本题使用 LLM，关联冻结的题目级评分提示词
```

- 选择题可以提供正确身份、儿童选择、是否正确等原始事实；如果无模型评分，则无需伪造一个 LLM 原始分。
- ISE 可能有不同量纲的语音总分与子指标；LLM 可能提供结构化多维评分。明确分数范围与字段语义，转换交给选定代码插件。
- 必须区分**真实零分**、**原始评分不存在**和**引擎技术失败**；不得用默认 0 掩盖等待评测或未产生可信分数。
- 原始结果在事实层不可变，可保留后续重评作为新评价记录；不能为了换算法而覆盖旧引擎实际响应。
- 不预先要求所有题型具有完全相同的 `metrics` 字段。评分插件仅声明自己消费哪些原始证据，遇到真实缺失时返回待处理/不兼容，不擅自制造分数。

## 7. 题目级「评分说明」与整卷评分算法的分工【本次修正，已确认】

题库 Excel 第 **N 列评分说明**：由教师在创建或修订题目时编写，按题型评测合同用于构造**LLM 原始评分的提示词**。例如儿童看图说话，教师规定应考察语言组织、图像相关性、表述完整性等。它不等于整卷权重、转换函数或档位。

典型流向：

```text
TaskRevision.N 评分说明 + 冻结的题目内容/TaskRevision.M 参考答案（按题型实际需要）
    → 题型评分适配层构造 LLM 评分请求
    → 模型返回原始结构化结果
    → 保存 RawEvaluation（保留提示词归属、模型身份和原始输出）
    → 已选代码评分插件转换与汇总
    → ScoreResult
```

- 不需要 LLM 评分的指令/图片选择题，不因存在 N 列就强制触发 LLM。
- 修改 N 列产生新的 `TaskRevision`；旧 PaperEntry 固定旧提示词，复制旧卷也保留旧提示词。
- 评分插件可以根据题型消费原始维度分，但**不重写 N 列提示词、不在运行时决定儿童对话轮次或录音提交**。
- 发布冻结题目版本时已同时冻结该题评分说明；评测运行时还应记录调用所用的提示模板或评测适配版本，保证原始结果可解释。
- 教师自主编写评价要求，不意味着系统可以保证模型遵守全部文字要求；原始 LLM 输出至少要满足该评分通道声明的技术结构合同，质量分析与模型提示优化可在离线测试进行。

## 8. 已部署代码插件：最小注册与调用合同【已确认方向】

```python
# 最小接口示意；以评分专项 S1.0 和按需评测 E1.0 为权威。
class ScoringPlugin:
    plugin_id: str
    implementation_version: str
    evaluation_requirements: dict

    def score_task(self, task_context, raw_evaluations, submission_facts):
        ...  # 原始评价与冻结事实 → 系统单题转换分

    def score_paper(self, paper_context, task_scores):
        ...  # 已采用单题分 → 整卷汇总与档位
```

- 插件在服务器代码中**静态注册**，教师在草稿组卷页从已注册候选中选择；注册项按业务名称展示，不要求教师理解内部版本号。
- 老师提出新公式 → 开发者实现新插件或新版本 → 定向测试 → 正常部署 → 之后新建或编辑草稿可以选择。无「在线公式编辑器」「运行时热加载」「插件代码上传」功能。
- 插件可以内部定义题型原始分映射、有效重播/求助处理、单题/题型聚合、总分与档位。单题转换、初始整卷汇总、复核后整卷再计算的时序以 S1.0 为准；评测来源按 E1.0 声明。**这是算法，不是题目业务 Handler**。
- 发布冻结 `plugin_id + implementation_version`。修改实现语义就注册新版本，不能在原身份下悄悄改变历史算法行为。
- 被旧 Paper 引用的实现不能随版本发布时移除到无法运行；可将其从新卷候选列表隐藏，但必须支持在途任务评分、历史核对及明确授权的重算。
- 插件不负责调用 LLM、ASR/ISE 或 TTS，也不决定 Attempt 封存、整题重做、是否完成目标轮数或 Submission 的成立；这些在业务层固定。
- 缺少必要 RawEvaluation 不能凭空变成分数。若允许教师人工复核代替缺失的自动评分，应由另一个明确的评分事实/复核合同提供，不得用一个随意的数值伪装为引擎输出。

## 9. 评分输入到正式结果的约束

- 仅已接受的 `Submission` 能成为当前 Attempt 的评分来源；`OPEN`（包括 LLM 生成下一轮失败）、`ABANDONED` 的 Attempt 不得计入本次正式结果。
- `Submission` 的有效重播/求助计数作为真实评分输入冻结；是否扣分、如何扣分由选中插件决定，业务层不先硬编码规则。
- 原始评价、转换结果和可选人工复核应分开保存并保留可追溯关系；不得修改模型/引擎原始返回以适应新规则。
- 所需原始评价未就绪时，结果是 `PENDING` / `INCOMPLETE`，不是数字零或“不合格”。插件的异常不能要求儿童自动重做已提交题目。
- `ScoreResult` 固定算法 ID 与版本、输入身份及计算摘要；一次正式结果生成后不随今后插件上线自动重算。若后续支持人工复核后的新正式版本，需清晰保留新旧结果。
- Session 是否可以最终结算由独立 Session 业务合同判断，评分插件只计算允许提交给它的已确认输入，不能绕过题目/整卷完成条件。

## 10. 验收矩阵

1. 新建试卷时同题库 D001 仅有当前最新、未归档版本可选；不展示历史版本选择器。
2. 新组卷可拖拽题序、替换整题，但不能编辑 TaskRevision 内容。
3. 已发布旧卷 D001=v2、题库现 v5：完整复制后新草稿仍引用 v2，不发起升级检查。
4. D001 已归档：旧卷及其复制草稿仍可引用原修订；新从题库选题不得选归档 D001。
5. 复制草稿只调整题序：修订仍是旧版本；复制草稿主动替换 D001：新条目才使用最新可用修订。
6. 复制包含旧的题目级 LLM 评分说明时，原样保留旧提示词；不读取当前 v5 的说明。
7. 复制原卷后无 Session/Submission/ScoreResult 被复制到新卷。
8. 复制旧卷原算法 r1，草稿仍选 r1；不能静默升级到 r2 或其他方案。
9. 原算法已无法运行时明确报告不可用，不擅自选择另一个算法。
10. 已发布试卷归档只影响新 Session 投放，不影响旧 Session 完成或历史查询。
11. 旧题归档不使旧卷失效，不能用最新题目可用性反向否定历史快照。
12. LLM 原始评分使用题目冻结的 N 列评分说明；无该评测需求的题型不强制调用 LLM。
13. 修改 N 列创建题目新版本，不改已有卷中的 N 文本或所选插件。
14. ISE/LLM/选择题返回不同结构与量纲，能够通过统一 `RawEvaluation` 协议记录，并按插件消费各自维度。
15. 原始零分、结果缺失和服务故障严格区分；不得以默认零分代替缺失证据。
16. 插件可以改变原始分换算、求助/重播处理和总分档位，但不能新增 Dialogue 轮次或覆盖儿童录音。
17. 新增算法必须通过代码部署并注册；教师端仅选择算法，无在线编辑或热加载入口。
18. 更新插件公式后使用新 `implementation_version`；旧卷版本和历史成绩不受影响。
19. 缺失必要评分输入的 Session 不得被输出正式总分或正式档位。
20. 已发布卷与题目删除只在不破坏已有引用时考虑；具体删除 UI 仍待最终业务确认。

## 11. 尚需另行确认，不能偷当定案

1. **普通新建草稿期间题库出现新修订**：原已选题模块是否自动刷新到最新、还是保留选入时的版本并发布前提示更新？复制旧卷**不参与**这个选择，永远按完整继承处理，除非教师主动替换模块。
2. **物理删除**：未被任何 Session 引用的已发布试卷及全无外部引用的题目是否提供删除入口？此前提出可以允许，但未收到最终确认。
3. **评测通道与字段契约**：各题型实际使用什么 LLM 评分输出 schema、哪些 ISE 指标、是否有人工复核替代自动评分，应在评分专项设计中审计而不是本稿预设。

**下一步**：用旧 `legacy_v1` 与 `trial_2026_v1` 两个实际算法验证统一 `RawEvaluation → ScoringPlugin → ScoreResult` 接口；随后进入 Session 生命周期和三种简单题型的专项设计。
