## 1. 目标与非目标

### 1.1 目标【确定】

Speaking 应在一条 Attempt 内支持多段录音、儿童反复主动求助、引导问题完整播放、独立的主动重播、儿童自主结束本题，以及故障后从服务端已确认事实继续运行。

必须可靠应对：重复网络请求、录音已保存但 ASR 失败、儿童无可识别表达、LLM/TTS 失败、主动重播期间的串行冲突与重复计数、客户端退出、操作并发、旧异步结果延迟返回，以及正式提交与后续异步评分脱钩。

### 1.2 非目标【确定】

- 不设计跨题型的万能状态机；Dialogue 的轮次逻辑不并入 Speaking。
- 不由 Speaking 决定整场 Session 的最终结算。
- 不由 LLM 自动提交或结束本题。
- 不预设固定学段白名单、引导次数上限、录音段数上限或 Attempt 次数上限。
- 不为低概率播放回执丢失设计秒级续播、**自动故障重播**或复杂取证系统；儿童手动点击“重新播放”属于独立的正常业务操作，不受此项非目标排除。
- 不重新定义教师已发布试卷的评分算法、人工复核或完整 Session 结算流程。
- 不为人为把最低时长错误配置为零等情况增设特殊业务兜底分支。

## 2. 职责与业务对象

| 对象/模块 | 主要责任 | 明确禁止 |
|---|---|---|
| `SpeakingHandler` | 解释 Speaking 事件、许可、当前运行政策及业务转换 | 直接决定整卷完成、修改其他题型状态 |
| `Attempt` | 某个 SessionTask 的独立作答身份与通用生命周期 | 承担题型定义或整卷计分 |
| `SpeakingSegment` | 一次已接收录音的身份、顺序、音频引用及识别事实 | 将 ASR 失败等同于录音不存在 |
| `SpeakingHelpRequest` | 儿童一次被接受的主动 `?` 点击及引导/交付进度 | 充当新的 Attempt 或正式 Submission |
| `PromptPlayback`（或等效播放事实记录） | 首次播放、引导交付和主动重播的操作身份、来源及交付事实；能够独立统计有效重播 | 以重播生成新问题、重复增加求助次数 |
| `AsyncOperation`（或等效持久化操作记录） | ASR、LLM、TTS 等调用的身份、状态、可恢复错误与技术重试 | 擅自裁决能否提交、能否重新作答 |
| `Submission` | 一次正式提交的固定输入范围及后台处理身份 | 记录未提交片段或直接决定 Session 总分 |
| 公共能力 | 可靠音频存储、ASR/LLM/TTS、后台处理与任务恢复 | 定义 Speaking 的结束标准 |
| 小程序 | 展示服务端许可、执行录音/播放、冻结冲突按钮 | 自行决定正式业务状态或计算权威求助次数 |

所有业务身份均应关联明确的 `SessionTask` 和 `Attempt`。`SessionTask` 轻量引用发布时已冻结的 `PaperEntry`；不复制整套题目内容。

## 3. 核心业务不变量【确定】

1. **一次当前作答**：同一 SessionTask 的正常交互只有一个当前作答入口；重新作答以原子切换创建新 Attempt，不在一个 Attempt 内清空录音重新开始。
2. **两类终止**：`OPEN` 可以因正式提交变为 `SEALED`，也可以因明确重新作答变为 `ABANDONED`；已经 `SEALED` 的历史提交事实不被改写，后续重新作答通过独立的候选资格 `SUPERSEDED` 表示旧作答被替代。
3. **服务端事实优先**：前端页面/加载变量不是权威状态。已经确认的音频、ASR、引导、交付、Submission 不因断网或技术故障而凭空消失。
4. **正常作答串行**：上传/必要 ASR、引导生成、引导播放、主动重播、正式提交期间，暂停其他相冲突的作答操作；服务端独立裁决，不依赖按钮置灰。
5. **用户自主结束**：时长达到当前政策要求后，页面可显示“结束本题”；即使内容不充分也可提交，正式评分据实处理。LLM 不拥有自动结束或自动提交权。
6. **空回答可求助**：没有录音、ASR 文本为空或被可靠判为无可识别内容时，允许主动求助。不得将服务故障假装成儿童沉默。
7. **求助不限次**：没有业务明确设置时，不设主动求助次数上限；重复请求、技术重试以及最终作废的求助不重复计数。
8. **独立技术重试预算**：外部技术故障可以有限次自动重试；耗尽后停止自动循环、提示系统错误、按断点恢复并解除交互冻结，不自动销毁 Attempt。
9. **可靠提交**：正式提交必须原子固定输入范围、建立 Submission 和封存 Attempt；后台评分不得提前领取半成品提交。
10. **提交后立即放行**：Submission 接受成功即可进入下一题，无须等待正式 ASR/评分及复核。
11. **当前政策与发布评分分离**：OPEN Attempt 的提交资格按当前生效 Speaking 运行参数判断；正式计分按已发布 Paper 绑定的评分算法和参数运行。
12. **无隐性业务上限**：仅允许真实业务规则或平台能力所需约束；不得从旧系统照搬小/中/大班许可白名单、固定求助次数、重播次数或总录音时长限制。
13. **重播不改变作答**：重播只读取当前应答的既有语音内容，完成后记入独立 `replay_count`；不重新生成问题、不增加求助、不改变录音/提交资格。
14. **模式仅是外壳**：小程序 `child/advanced` 只影响哪些控件和诊断字段可见；切换不创建、删除、重置或重放任何业务事实。
15. **LLM 仅校验技术有效性**：至少得到可解析 JSON 对象和有效的非空引导文本；不以句式、问号数量、字符级重复/相似性等内容质量规则阻断流程。

## 4. 生命周期、业务阶段与操作许可

### 4.1 Attempt 生命周期

```text
OPEN ──[提交事务成功]──────────────> SEALED
  └───[明确重新作答，原子切换]────> ABANDONED

SEALED ──[之后明确重新作答]───────> SEALED + SUPERSEDED（计分候选失效）
```

`SUPERSEDED` 是候选资格/替代事实，不要求改写 Attempt 的已提交生命周期。

### 4.2 Speaking 业务阶段（推荐投影，而非必须持久化六个枚举）

| 阶段 | 从什么事实识别 |
|---|---|
| `WAITING_INPUT` | Attempt OPEN，当前无未完成的独占操作 |
| `RECEIVING_AUDIO` | 上传/持久化操作尚未确认完成 |
| `ANALYZING_AUDIO` | 片段已保存，必要的 ASR 尚未完成 |
| `GENERATING_GUIDANCE` | 求助已被接受，LLM 尚未产出有效引导 |
| `DELIVERING_GUIDANCE` | 引导已生成，必要 TTS/播放交付尚未完成 |
| `RECOVERABLE_ERROR` | 某项技术操作停止自动重试，等待人工重新触发或重新作答 |

具体状态优先由 Segment、HelpRequest 和异步操作的持久化事实推导；避免多个可互相矛盾的 `phase` 权威字段。

### 4.3 用户操作许可矩阵【确定】

| 当前阶段 | 录音/提交片段 | 点击 `?` | 重新播放 | 结束本题 | 重新作答 | 查询/恢复 |
|---|---|---|---|---|---|---|
| `WAITING_INPUT` | 允许 | 允许 | 有可用当前语音时允许 | 仅满足提交资格 | 高级模式显示入口 | 允许 |
| `RECEIVING_AUDIO` | 暂停新操作 | 暂停 | 暂停 | 暂停 | 暂停 | 允许 |
| `ANALYZING_AUDIO` | 暂停 | 暂停 | 暂停 | 暂停 | 暂停 | 允许 |
| `GENERATING_GUIDANCE` | 暂停 | 暂停 | 暂停 | 暂停 | 暂停 | 允许 |
| `DELIVERING_GUIDANCE` | 暂停 | 暂停 | 暂停 | 暂停 | 暂停 | 允许播放/交付处理 |
| `REPLAYING_PROMPT`（临时操作投影） | 暂停 | 暂停 | 暂停新的重播 | 暂停 | 暂停 | 允许 |
| `RECOVERABLE_ERROR` | 按实际断点 | 原操作解除后可重新发起 | 解除冲突且有可用语音时允许 | 按当前资格 | 高级模式显示入口 | 允许 |
| `SEALED` | 不允许 | 不允许 | 终止作答播放入口 | 返回已接收结果 | Session 许可下显示重做入口 | 允许 |
| `ABANDONED` / 已替代旧作答 | 不允许 | 不允许 | 不允许 | 不允许生成新提交 | 在当前新 Attempt 操作 | 只读历史 |

`REPLAYING_PROMPT` 仅表示一次正在执行的独占播放操作，**不是 Attempt 生命周期的新状态，也不要求新增独立持久化阶段枚举**。“暂停”只针对相冲突的作答操作；不能禁止状态查询或恢复操作。小程序按钮是否可见取决于界面模式；服务端的业务许可始终按实际 Attempt 和操作事实计算，不把 `ui_mode` 当成状态机输入。成功解除或错误退出后，小程序的可点击动作由服务端重新投影，不依赖陈旧的 `loading=true`。

### 4.4 前端状态投影【实现建议】

服务端响应至少能表达：`attempt_id`、生命周期、当前阶段、已确认音频/引导进度、当前可重播语音的身份与可用性、有效 `replay_count`、当前未完成操作及其状态、当前时长与门槛的达标结果、`allowed_actions` 和必要失败提示。字段命名、URL 留待接口设计。

已满足当前提交条件时，在录音按钮附近展示“结束本题”，可辅以纯视觉达标提示；**不另外生成“你可以结束了”的语音提示**。儿童仍可继续录音、点击 `?`，或在无冲突操作时重新播放。

**双模式纯前端外壳【确定】**：默认儿童模式；长按题型标题进入高级模式，仅改变可见的按钮和调试字段（如“重新作答”）；切换时沿用相同的 Attempt、Segment、HelpRequest、播放状态与所有计数事实。服务端不维护 `child/advanced` 业务状态，也不因为切换而重新加载为新 Attempt、自动播放或清空录音。高级模式入口隐藏不是身份验证；初版接受这是内部施测工具的使用取舍，不额外引入权限系统，但现有 SessionTask/Attempt 归属及事务合法性检查不能省略。

## 5. 事件—前置条件—转换—持久化合同

下述名称为推荐事件标识；允许调整实现命名，但不能改变其业务含义。

| 事件 | 前置条件/许可 | 必须产生或确认的事实 | 成功后 |
|---|---|---|---|
| `START_ATTEMPT` | SessionTask 允许开始作答 | 新 Attempt 身份 | `OPEN/WAITING_INPUT` |
| `SUBMIT_SEGMENT` | `WAITING_INPUT`、当前无冲突操作 | 稳定 Segment 身份、可靠音频文件及引用 | Checkpoint A，进入必要识别 |
| `ASR_COMPLETED` | 对应 Segment/ASR 操作身份有效 | 真实文本或合法“无可识别内容”语义及证据 | Checkpoint B，回到 `WAITING_INPUT` |
| `ASR_TECHNICAL_FAILURE` | 有相关 ASR 操作 | 失败类别、技术尝试与恢复信息 | 同一操作重试或可恢复错误 |
| `REQUEST_HELP` | `WAITING_INPUT`，**允许没有录音** | 一条儿童主动点击对应的 HelpRequest、当前输入断点 | `GENERATING_GUIDANCE` |
| `GUIDANCE_GENERATED` | 归属及输入断点仍有效 | 引导文本与请求关联 | Checkpoint C，进入交付 |
| `GUIDANCE_DELIVERED` | 对应引导成功完整播放 | 交付确认、一次有效求助 | Checkpoint D，回到 `WAITING_INPUT` |
| `REQUEST_REPLAY` / `REPLAY_CURRENT_PROMPT` | `WAITING_INPUT`、无冲突操作且当前语音已存在 | 稳定的本次用户重播操作 ID、被重播语音引用、来源为主动重播 | 独占播放，临时冻结其他作答操作 |
| `REPLAY_DELIVERED` | 该次主动重播完整播放且确认 | 一次有效重播交付事实；不修改原引导/录音 | `replay_count` 可增加一次，回 `WAITING_INPUT` |
| `REPLAY_FAILED` | 播放失败或无法完成交付 | 失败事实，不计有效重播 | 解除播放占用，保留原作答进度 |
| `HELP_FAILED_VOIDED` | 生成/交付确认失败且自动恢复已停止 | 本次求助作废，保留审计事实 | 恢复最近可靠业务断点，解除占用 |
| `REQUEST_FINISH` | `WAITING_INPUT`，当前提交条件满足 | 开始最终提交校验 | 进入原子封存流程 |
| `SUBMISSION_ACCEPTED` | 同一事务复核全部条件成功 | 固定输入清单、Submission、Attempt `SEALED` | 允许下一题，后台待处理 |
| `RESTART_ATTEMPT` | 当前 SessionTask 允许重做，无未完成冲突事务 | 旧作答退出候选、新 Attempt 创建 | 新 Attempt `WAITING_INPUT` |
| `RESUME_ATTEMPT` | 请求者有权访问 | 读取原有事实与操作，重新计算合法动作 | 不自动创建 Attempt、Segment、HelpRequest 或 Submission |

任何成功落库的异步结果，都必须核验所属 Attempt、操作身份和必要的输入进度。废弃/已替代旧 Attempt 的迟到结果不得影响新 Attempt。

## 6. 四类 Checkpoint：事务边界与恢复

**Checkpoint 是最近可恢复的已确认业务事实边界，不是完整内存快照。**<br>
A/B/C/D 是 Speaking 操作循环中可反复出现的断点类型，不是一次 Attempt 只能经历 A→B→C→D 各一次。

| 断点 | 何时成立 | 能从哪些事实识别 | 出错后的最低恢复保证 |
|---|---|---|---|
| **A：录音保存** | 音频文件与 Segment 记录均可靠保存 | `SpeakingSegment` + 稳定 `audio_asset_id` | 不丢录音；可针对同一片段恢复 ASR |
| **B：识别确认** | 有效识别结果（含“无可识别内容”）保存 | Segment 的 ASR 结果/对应操作 | 后续求助能读取真实累计 ASR |
| **C：引导生成** | 有效引导文本被保存并绑定求助 | `SpeakingHelpRequest` + 引导结果 | 可以交付已经生成的引导，不能假装已播放 |
| **D：引导交付** | 播放完成事件被服务端接受 | HelpRequest 的已交付事实 | 该求助计为一次有效点击，允许继续作答 |

业务在两个断点间失败时，可以舍弃**未正式接受的临时输出**；不能删除先前已成功确认的录音/识别/引导事实。

**本版刻意不实现**音频播放到第几秒的断点、播放完成回执丢失后的复杂自动重播策略。确认失败时可将求助作废、恢复并允许儿童再次主动求助；已有持久化历史保留以便审计。

## 7. 录音接收与 ASR 合同

### 7.1 录音（Checkpoint A）

推荐流程：

1. 客户端生成本次录音稳定 `segment_id`；同一次网络重传复用该身份。
2. 服务端执行必要的音频格式、文件完整性与归属验证。
3. 将音频可靠保存为公共 Asset，取得稳定引用和必要完整性信息。
4. 在数据库事务中确认对应 Segment，记录所属 Attempt、顺序、服务端核验时长和音频引用。
5. A 成立后再执行必要 ASR；不要将 ASR 成功作为是否保存录音的前置条件。

数据库与文件存储没有天然共同事务。应避免“数据库已确认，但音频实际不存在”；数据库登记失败后产生的孤立文件可按明确维护流程清理，不构成抹除已确认录音的理由。

重复提交语义：相同 Segment ID + 相同内容返回既有确认；同 ID + 不同内容报告身份冲突；真实新录音使用新 ID。片段数量不设任意业务上限。

### 7.2 ASR 结果必须区分语义与技术故障【确定】

| 规范化语义类别（建议） | 依据 | Speaking 处理 |
|---|---|---|
| `TRANSCRIBED` | 已可靠得到文本 | 保存真实文本，Checkpoint B |
| `NO_RECOGNIZED_SPEECH` | 服务商明确返回“无可识别语音/文本”等**业务语义** | 保存空文本及原因，Checkpoint B |
| `LOW_CONFIDENCE` | 服务商明确返回低置信度信息 | 保留其真实证据；仅在适配规范证实可作为无可识别内容时做相应映射 |
| `PROVIDER_ERROR` | 网络、超时、鉴权、接口异常、供应商内部故障等 | 保留 Checkpoint A，执行技术恢复策略 |

以上**不是讯飞真实错误码表**。实施前必须核对所用 ASR 产品、API、响应字段和错误码，将实际错误精确映射；不能凭数字或笼统的非 2xx 状态自行推断“儿童沉默”。无法确定语义的错误不应静默改写为空回答。

- 空 ASR 是**真实识别文本为空**，不是字符串 `"儿童没有说话"`。
- 必要时可在**引导 LLM 的提示词说明**中表达“儿童没有说话／目前没有可识别的回答内容”，并说明这是引导上下文而非儿童原话；不得写入 `asr_text`。
- 没有录音而直接求助时，输入进度为空，模型依题干生成适龄开放问题。
- 明确的技术故障按技术策略重试；成功但无可识别文本不触发无意义的无限 ASR 重试。
- 正式评分相关的 ISE/ASR 原始证据与此处的**过程引导识别**分开；不得伪造原始文本或评分数值。

### 7.3 ASR 自动重试耗尽

保留最后成功的 Checkpoint A，停止本轮自动循环，记录错误并向页面展示简单“系统错误”提示。原 Attempt 不自动作废，已保存音频不删除。

再次执行必须来自明确的恢复/重试动作或新的业务操作，不能因每次页面刷新又自动重新获得无限重试预算。若某段必要 ASR 未完成，不能把它假冒成空回答后强行跨越依赖继续执行。

## 8. 主动求助、LLM 合同与交付计数

### 8.1 一次真实点击 = 一次独立求助身份

儿童每次在允许阶段主动点击 `?`，服务端接受时创建一条 `SpeakingHelpRequest`。请求至少能识别：

- `help_request_id`、`attempt_id`、操作来源 `child_requested`。
- `input_frontier`：本次求助引用的**已确认**片段/累计 ASR/已交付引导历史。
- 处理阶段、必要技术操作身份、引导内容引用、交付结果。
- 该操作最终是否有效，或者是否因技术故障作废。

网络重复发送相同业务操作身份返回同一条请求；冻结期间来自重复点击的新请求不应再次被接受。同一求助内部的 LLM/TTS 自动重试不产生新求助身份。

### 8.2 Speaking 主动求助模型输出合同【确定】

**删除** `should_end`，不允许 `content_sufficient → 自动结束` 的控制路径。模型只生成适当的引导问题。建议最小技术合同：

```json
{
  "guidance_text": "你能说说为什么喜欢这种动物吗？"
}
```

**必须校验可解析的 JSON 对象、必需的 `guidance_text` 字段为非空字符串。** `reason_code` 等审计元数据可选，是否保留留待接口设计；不得重新引入自动结束标志。对非 JSON、字段缺失、类型错误或空文本，按同一技术操作有限重试，耗尽则作废并解冻。**不以字符长度、问号数量、语言风格、历史问题相同或相似度等语言内容质量规则拒绝、反复重生成或阻断儿童作答。**

生成提示词的质量目标（不是运行时硬性质量校验）：

- 根据题目、学段上下文（不作为题型许可白名单）、当前可用真实 ASR、历史引导生成自然、适龄、具体的开放问题。
- 已无可识别文本时，提示词可明确说明“儿童没有说话／当前没有可识别回答”，**不可写入原始 ASR 字段**。
- 不提供参考答案、示范句或诱导性内容；尽量避免机械或重复追问。
- 即使当前已经满足提交门槛，儿童点击 `?` 仍正常生成引导；不自动提交，也不播放额外的“你可以结束了”提示。
- 模型输出**技术上不可用**时由相同求助的有限技术恢复流程处理；文本质量不理想时不触发内容质量拒绝或不断重生；不得通过无意义的固定次数限制终止儿童业务能力。

### 8.3 引导播放与计数【确定】

求助接受后直至引导正常完整播放，**冻结 Speaking 作答交互**：禁止新录音、新求助、结束本题及正常重新作答。TTS/播放器执行属于交付操作的一部分。正常完整播放并经服务端确认后形成 Checkpoint D，解除冻结。

不支持儿童主动跳过/打断当前引导直接录音；小程序意外退出或音频交付失败则进入简化故障处理，不要求复杂续播。

**求助有效计数：**

```text
effective_help_count
  = COUNT(当前被正式选用的 Attempt 中，
          来源为儿童主动点击且最终成功交付、
          未因故障作废的 HelpRequest)
```

含义是“有效的真实主动点击”，不是 HTTP 请求数，也不是后台调用次数。LLM/TTS 自动重试、相同点击的网络重传、最终失败作废的求助不计数。

**不采用独立权威计数器的 `+1/-1` 回滚算法。** 以求助事实及其终态推导，避免重复异常回调导致多减、迟到结果重加。播放完成确认应具幂等性。

### 8.4 求助失败的简化路径

LLM/TTS/交付经自动技术恢复仍未成功时，记录本次求助失败并作废，保持已有 Checkpoint 事实，向页面提示“系统错误”，**解除独占交互并允许儿童再次主动点击 `?`**。不自动创建 Attempt；不强制区分教师/儿童错误界面；不为极端播放回执丢失引入额外自动重播机制。

注意：**“本次求助作废”指不参与有效计数与当前引导流程，不是物理清除已经持久化的求助、模型和错误审计记录。**

### 8.5 独立主动重播机制【确定】

**业务目的**：允许儿童在正常作答阶段再次听到最近一条应回应的语音，且将主动重播次数独立记录，供未来已发布单题转换算法按明确规则使用。重播不是求助、不是新的录音、不是新的 Dialogue 轮次，也不是自动故障重播。

**重播内容选择（由 SpeakingHandler 决定）**：

1. 当前 Attempt 尚无**成功交付的引导**：重播本题发布版本确定的初始题目语音。
2. 已存在成功交付的引导：重播同一 Attempt 中**最近一次成功交付**的引导语音。
3. 新求助尚在生成/交付中：重播与其他作答操作均暂时不可发起；若该求助失败作废，解除占用后仍指向先前最近成功交付的引导（如无则原题）。
4. 题目版本或初始语音资源不得因为题库后续导入修改而发生漂移；若当前应播放的资源尚未可用，则报告资源不可用，不悄悄改播其他内容。

**播放与交互串行**：只在 `WAITING_INPUT` 且有可用当前语音、没有其他独占操作时接受主动重播。调用公共音频播放能力，播放期间冻结新的录音、求助、正式提交、其他重播与正常重新作答；完整播放或失败解锁后回到同一 `WAITING_INPUT`，不改变已有 Checkpoint A/B/C/D。可以把“正在重播”投影为短暂 UI 状态，**不另建一套重播状态机**。

**计数身份及语义**：

```text
有效 replay_count = COUNT(
  当前 Attempt 中由儿童主动点击“重新播放”产生、
  对应播放完整交付且未被判定失败的独立重播操作
)
```

- 第一次正常播放题目、求助产生引导后的正常首次播放，不算重播；**只有主动点击“重新播放”才可能进入此计数**。
- 每次被接受的主动重播点击对应独立稳定的 `replay_request_id`；同 ID 的网络重传或播放完成确认重传只认同一操作，不重复计数。
- 完整播放并被确认才算一次有效重播。播放失败、系统重试、尚未完成交付的操作不计数；恢复时不通过 `replay_count += 1/-=1` 做不可审计的补偿。
- 重播始终播放**已有问题/引导**，不调用 LLM 重新生成内容；复用已确定语音资源，不新增 HelpRequest，也不增加 `effective_help_count`。
- 重播次数默认没有业务上限；**不预设扣分公式**。总计分依据是当前被正式提交的 Attempt 的有效重播事实，与求助计数独立。
- 为初版简单可靠，不设计播放进度续播、回执丢失后自动重播、额外复杂的播放取证；一般失败释放操作占用并提示用户按需重新点击。

**公共/专属边界**：公共播放记录与资源服务保存`原始播放/首次引导交付/主动重播`的操作来源、资源引用及结果；SpeakingHandler 决定当前选择原题还是最近成功交付的引导、是否允许本次播放，并把有效重播事实纳入 Submission 输入。Dialogue 可以复用同一技术能力，但由 DialogueHandler 选择当前 Turn 问题。不得因复用而建立跨题型万能作答状态机。

## 9. 操作串行、事务与异步故障恢复

### 9.1 并发原则【确定】

同一当前 Attempt 的互斥业务操作只允许按顺序生效。前端依据服务端 `allowed_actions` 禁用冲突按钮；服务端依靠原子条件更新、必要唯一约束或等效数据库事务机制**再次裁决**。不依赖进程内锁作为唯一真相。

- 与已有操作身份相同：恢复/返回原操作结果。
- 不同身份的冲突操作仍在进行：不接受新的状态转换，返回当前操作的状态。
- 已提交或已废弃 Attempt 的旧异步结果：不能修改新 Attempt，不能产生当前有效成绩或引导。
- 自动重试必须绑定**原操作身份**和适用输入事实，不创建新 Segment、HelpRequest、重播身份、Attempt 或 Submission。
- 正在主动重播时与上传、ASR、求助、引导首次播放、正式提交互斥；不同重播请求不能同时生效，同一重播 ID 幂等返回。
- 自动重试次数/间隔/超时是可配置的**技术运营参数**，不是儿童求助/录音/作答次数限制；不在本专项写死具体数字。
- 技术重试耗尽后停止自激活循环，保存故障事实，返回最近可靠断点和当前合法动作。

### 9.2 故障与断点选择

| 故障 | 应保留的事实 | 业务恢复 |
|---|---|---|
| 片段已保存但 ASR 调用失败 | Segment、音频、Checksum | 恢复 A，对该片段重新执行合法识别操作 |
| ASR 结果为空但被规范化为无可识别内容 | 真实空文本及来源状态 | B 成立，可继续录音或求助 |
| LLM 调用失败 | 已完成的录音/识别、求助请求身份、错误事实 | 自动重试原求助；最终失败则作废并解锁 |
| 引导文本已保存但播放失败 | C 及失败记录 | 本次求助可作废，解锁；不实施复杂自动故障重播 |
| 主动重播过程中播放失败 | 原题/原引导成功交付事实、失败的重播操作 | 解锁并返回原作答阶段；有效重播次数不增加，先前求助不受影响 |
| 网络重复提交录音或求助 | 已确认原事实 | 返回既有操作，不重复保存/计数 |
| 客户端重新进入 | 所有服务端已确认事实 | 查询原 Attempt，不自动新建实例或求助 |
| 旧 Attempt 废弃后外部结果迟到 | 旧数据归属 | 禁止修改新的当前 Attempt |

## 10. “结束本题”与 Submission 原子提交

### 10.1 提交资格【确定】

- 只由儿童在 Speaking 页面明确点击“结束本题”发起。
- 当前 Attempt 为 `OPEN`，属于允许作答的 SessionTask，当前无未完成的互斥作答操作。
- 当前有效 Speaking 运行规则中的最低时长等**已明确条件**得到满足，使用服务端已确认音频事实核算。
- **不以 LLM 内容充分性作为额外提交门槛。** 内容不足如实交由正式评分；儿童仍可在达标后选择录音或求助。
- 不为业务方已经视为错误配置的 `minimum_duration=0` 增设专门的运行时“空提交兜底”分支。

### 10.2 正式接受的一次数据库原子事务【确定】

同一个事务必须：

1. 在最终写入时复核 Attempt 的归属、当前身份、生命周期、独占操作与实时提交政策。
2. 固定本次 Submission 的输入清单：确认的 Segment ID 顺序及稳定音频引用，以及当时有效的主动 HelpRequest **和主动重播**的事实范围/独立计数依据。
3. 原子建立唯一的正式 Submission 与可供后台领取的处理身份，并将 Attempt 从 `OPEN` 封存为 `SEALED`。
4. 成功提交后才对客户端报告“本题提交成功”，后台才允许领取 Submission。

事务失败则不能出现“Attempt 已 SEALED，但找不到 Submission”，或“Submission 已接受，但 Attempt 仍可追加录音”的半提交状态。

ASR/ISE/评分等耗时的外部调用不得在该数据库提交事务内部执行。异步 Worker 可以在**提交成功后**使用已固定的原始音频和事实做后续处理；它不要求儿童等评分结果。

### 10.3 提交幂等与前端放行

- 同一 `finish_request_id` 网络重传返回原有提交。
- 不同请求也不得在同一已 SEALED Attempt 上创建两份互相冲突的正式 Submission。
- 提交事务及其最终确认之前，前端不开放重新作答或下一题入口；提交成功后立即允许进入下一题。
- 旧 Submission 的正式评分失败时，恢复同一 Submission 的处理；不能让儿童再提交一次来“修复”后台处理。
- 后台总分和必要人工复核均属于后续流程，不影响儿童成功提交本题的定义。

### 10.4 已提交后重新作答【确定】

正式提交事务完成后，若 SessionTask 的当前生命周期允许，可由**高级模式下显示的重新作答入口**明确发起重做（通常由现场施测者操作）。这只是小程序控件可见性安排，服务端仍按已有 Attempt/SessionTask 业务合法性执行，不读取 `ui_mode` 作为权限标志：

- 若旧 Attempt 仍 `OPEN`：一个事务将其 `ABANDONED` 并创建新 Attempt。
- 若旧 Attempt 已 `SEALED`：保留其已发生的 Submission 事实，**原子标记它已被替代并创建新的当前 Attempt**。
- 新 Attempt 从头作答，录音、求助计数、Submission 与旧 Attempt 不共享可变业务事实。
- 旧 Submission 即使尚在后台评分，其结果也不能影响新 Attempt 或变成当前的有效正式成绩。
- 已正式固化 `ScoreResult` 的 Session 不允许再改变有效作答。**【跨域待定】** Session 已请求整卷结算、但尚待处理或复核时，是否允许新增 Attempt，由 Session 专项确定。

**【重要的已确认业务更新】** 明确点击“重新作答”意味着主动放弃旧作答的候选资格。因此，新 Attempt 即使最终未形成有效 Submission，也**不能悄悄回退至这次明确已废弃的旧 Attempt 计分**。这修订了总体架构初稿“较新的未完成 Attempt 不应替代旧有效 Attempt”在**显式重新作答**情景中的解释；一般非主动废弃/误创建 Attempt 的候选规则仍由通用评分专项确定。应同步修订总体架构文档，避免互相矛盾。

## 11. 时效与评分输入边界

| 信息 | 权威来源 | 时效约束 |
|---|---|---|
| Speaking 最低时长等提交资格 | 当前生效题型运行参数 | 未提交 Attempt 每次判定读取当前值 |
| 已确认 Segment、ASR、求助/交付 | 已保存 Attempt 业务事实 | 不因运行参数变化而重写或抹除 |
| 提交输入范围 | Submission 在接受时冻结的 manifest | 提交后不可追加修改 |
| 有效主动求助次数 | 被 Submission 冻结引用的、已完成交付的儿童点击记录 | 当前候选 Attempt 独立统计 |
| 有效主动重播次数 | 被 Submission 冻结引用的已完成主动重播操作 | 与帮助次数独立统计，不含初次播放或失败的播放 |
| 原始 ASR/ISE/LLM 评分 | 外部真实结果和原始证据 | 不掺入“儿童没有说话”之类提示词说明 |
| 单题转换算法/助求助次数折算 | 发布 Paper 时固定的算法版本与参数 | 不被后来教师修改的默认评分标准追溯改变 |
| 人工复核、整卷正式结果 | 评分领域与 Session 结算流程 | 必要复核完成后原子固化结果 |

**【跨域待定】** 求助次数与主动重播次数具体影响分数的公式、舍入、权重或是否按梯度计算，必须在 Speaking 单题转换算法专项明确。**不得在本文或初版代码中擅自规定“每次求助/重播扣 X 分”。**

## 12. 初版验收测试合同

以下测试应优先作为确定性单元/集成测试；外部服务使用可控替身，不依赖碰运气复现竞态。

### 12.1 基础作答与门槛

1. 任意已注册学段上下文均能通过 Speaking 题型入口，不因 `small/middle/large` 白名单被拒。
2. 多段录音独立保存；已确认段数与累计时长由事实推导。
3. 当前最低时长配置变化后，未提交 Attempt 重新按当前门槛判定，历史录音不丢失。
4. 达标但内容不充分，仍可主动结束本题；未达标不得由 LLM 建议绕过。
5. 达标后继续录音/主动求助，**不自动提交**；无需额外结束语音提示。
6. 用户真正点击“结束本题”并完成事务后，才能创建正式 Submission。

### 12.2 ASR 语义

7. 没有任何录音即可点击 `?` 求助。
8. ASR 明确返回无可识别语音时，Checkpoint B 保存空文本，LLM 获得“儿童没有说话／无可识别内容”的独立提示说明。
9. ASR 真实文本字段中不出现由系统注入的沉默提示语。
10. ASR 网络超时/服务异常时，Checkpoint A 保留且不能将错误映射为儿童沉默。
11. 低置信度和服务商错误码使用**经过核验的适配映射**，未知码不擅自归类。
12. 自动重试耗尽后停止自动循环并解锁，不丢此前确认的录音。

### 12.3 主动求助与交付

13. 同一次真实点击仅创建一个 HelpRequest；同 ID 网络重传、技术重试不重复计数。
14. 儿童多次**独立成功求助**均可发生，不存在隐藏默认次数上限。
15. 求助中及完整播放前，录音、再次求助、结束本题、正常重新作答均不可被服务端接受。
16. 完整播放并确认后计为一次有效求助，恢复交互。
17. LLM/TTS 最终失败的求助标记作废，不计有效次数；恢复断点并允许再次点击。
18. 播放交付确认重复送达不重复计数。
19. 求助时已有录音/引导历史被绑定为明确的输入进度，迟到结果不引用其他 Attempt 的事实。
20. LLM 返回合同不含 `should_end`，不允许凭模型结果生成 Submission。
21. 达标后仍点击求助，正常生成具体开放式引导，而不是自动提交或特殊结束提示。

### 12.4 并发、断点与正式提交

22. 音频文件可靠保存后 ASR 失败，恢复使用原 Segment，不要求重新录音。
23. 录音已保存而成功响应丢失，重传返回原 Segment，不重复追加。
24. 同一时刻求助与录音/结束本题冲突，至多一个符合许可的状态变更被接受。
25. 重新打开小程序从服务端事实恢复，不自动新建 Attempt/HelpRequest。
26. 完成提交时三个动作——冻结 manifest、创建 Submission、Attempt SEALED——同一事务成功或全部回滚。
27. Worker 在事务提交成功之前不能领取尚未完整固定输入的 Submission。
28. 提交成功后立即允许下一题；评分或复核仍在后台运行。
29. `finish_request_id` 重传或不同 ID 的竞争提交均不产生重复正式 Submission。
30. 正式提交事务未完成时不允许重新作答；完成后允许原子创建新 Attempt。
31. 旧 Attempt 已被明确替代，其迟到 ASR/LLM/评分结果不污染新 Attempt、不成为当前候选成绩。
32. 显式重新作答后新 Attempt 未完成，不偷偷回退已被明确放弃的旧 Attempt 成绩。
33. Submission 评分失败恢复同一 Submission，不新建作答。
34. 已正式结算 Session 禁止重新作答改写正式结果。

### 12.5 主动重播、界面模式及 LLM 技术合同增量验收

35. Speaking 没有成功交付的引导时，主动重播本题初始语音；已有多条有效引导时，只重播最近成功交付的引导。
36. 较新的引导生成或交付失败并作废后，重播仍指向最近一次**成功交付**的引导，不误播失败内容。
37. 主动重播成功不新增 HelpRequest、Segment、Submission，也不再次调用 LLM；Speaking 已存在的录音事实与 Checkpoint A/B/C/D 均不改变。
38. 初次正常播放和求助后首次正常引导播放不计 `replay_count`；每次完整交付的独立主动重播各计一次。
39. 重播请求 ID 重传、播放交付确认重复送达均不重复计数；失败/未完成播放不计有效重播次数。
40. 录音、ASR、求助生成、引导播放、正式提交进行时不接受新重播；重播期间禁止相冲突操作，播放成功或失败均能解除占用。
41. 有效 `replay_count` 与 `effective_help_count` 相互独立；Submission 原子冻结两种事实，旧 Attempt 被重做后不与新 Attempt 混算。
42. 同一 Attempt 在儿童模式与高级模式间切换，只改变可见按钮/诊断字段，不影响当前片段、引导、正在播放的资源、提交状态及两个计数。
43. 儿童模式不显示“重新作答”，高级模式显示；模式字符串不是服务端状态或绕过 Attempt/SessionTask 事务合法性的许可。
44. Speaking LLM 返回有效 JSON 且 `guidance_text` 为非空字符串即可进入生成完成流程；**重复历史问题、标点、问号数量、句子长度和措辞风格不作为在线拒绝规则**。
45. LLM 返回非 JSON、缺失 `guidance_text`、错误类型或空文本时，触发有限技术重试；耗尽后作废本次求助、解除冻结，不虚构引导。
46. 提交后从 Submission 固定的输入读取有效主动重播事实；未配置重播扣分公式时，不擅自在题型状态机内进行扣分。

## 13. 实施约束、待协同事项与文档更新

### 13.1 建议实现顺序【实现建议】

1. Speaking Attempt/Segment/HelpRequest 业务事实与四类断点。
2. 公共 ASR 规范化适配及语义/技术故障映射，录音先存后识别。
3. 稳定操作身份、串行许可、有限技术自动重试与解除冻结。
4. 主动求助 LLM 最低技术输出合同、TTS/完整交付、有效求助计数；复用公共播放能力加入主动重播及独立计数。
5. “结束本题” Submission 原子事务及交给后台处理。
6. 明确重新作答的候选资格切换、迟到结果隔离。
7. 面向上面验收用例的确定性并发、故障与恢复回归。

顺序是合理拆分建议，不要求一个 PR 必须实现全部模块。

### 13.2 必须与其他专项协调，但不阻止 Speaking 主干落地

- **ASR 厂商适配**：核查真实讯飞接口的“无可识别内容”、低置信度、外部服务错误代码和语义；禁止编造对应码。
- **Speaking 单题转换评分**：确定有效主动求助次数、主动重播次数分别如何影响分数；须对齐发布时冻结算法，并保留原始分；不得硬编码默认扣分。
- **Session 结算边界**：正式结算完成后禁止重新作答；结算请求已提交但仍在评分/复核时的可否重做，交由 Session 专项确定。
- **总体文档一致性**：同步修订 `VNEXT_INITIAL_ARCHITECTURE_DESIGN.md` 第 5.3 节及相关验收表，区分“显式废弃旧作答”和“非废弃的新建 Attempt 尚未有效”。
- **接口/存储技术选型**：表结构、音频 Asset 实现、事务和唯一约束、主动重播记录身份/来源、客户端播放完成回执具体字段，可依据落地技术设计；不能改变本文件的业务行为。
- **题库版本管理**：本题初始语音来自已发布 PaperEntry 的不可变题目版本；题库相同业务 ID 的后续 Excel 导入和修订不得影响旧试卷重播资源。
- **外部故障技术政策**：配置合理的自动重试预算、超时与重试间隔，但不将其变成儿童作答上限。不要在业务核心硬编码厂商默认值。

### 13.3 明确禁止的历史问题回流

- 通过固定两次/三次求助、重播上限或假设最多若干段录音防止死循环。
- 因学段不属于固定白名单就拒绝 Speaking。
- 录音已可靠保存却因 ASR 失败删除录音，要求儿童全部重录。
- 把“儿童没有说话”写入真实 ASR 文本或伪造服务商原始评分。
- 将 ASR 的技术故障和无可识别语音视为同一种错误。
- LLM 自行决定 `should_end` 并创建正式 Submission。
- 因为问句与上一条完全相同/相似、标点不符、问号过多或句子较长就无限拒绝已具备非空 JSON 文本的模型输出。
- 将主动重播误计为 Speaking 求助、重新生成引导，或者把首次题目/引导播放误计为用户主动重播。
- 将小程序 `child/advanced` 模式切换当成创建/废弃/重置 Attempt 的服务端事件。
- 把“最后一段已上传”视为“全部正式输入已提交完整”，让 Worker 提前处理。
- 依靠前端按钮禁用实现唯一并发保护，或故障后使交互永久冻结。
- 以 `help_count += 1/-=1` 作为独立权威状态，而不依据被接受的有效求助事实。
- 后台 ASR/LLM 失败就自动新建 Attempt、Submission 或将旧结果写入新作答。
- 把已被儿童明确放弃的旧成绩隐式恢复为当前有效成绩。
- 因为“系统健壮”而增加没有用户授权的复杂兜底流程、人工异常界面或额外业务次数限制。
