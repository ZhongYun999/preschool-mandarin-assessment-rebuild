# VNext｜跨模块实施合同 C1.0（初审稿）

> 日期：2026-11-13。基础：新仓库 `docs/update-design-t1-5` 的 `07e491016661f22a3efee2fcef5d661b4094fb9b`。<br>
> 本文件是**最后一轮实施前的跨域整合草案**：`【确定】` 表示已在专项设计或会话中确认的行为，`【实现建议】` 表示可以调整的落地方式，`【待定】` 表示**不授权 Codex 擅自决定**的业务功能。<br>
> 不改写五种题型状态机、Excel T1.5、S1.0 双阶段评分或 SW1.1 Session 规则。旧总体设计/PROBLEMS 中不一致的历史表述，以后续已确认专项为准。

## 1. 实施范围和最小共识

- **【确定】** 五种题型仅通过各自 Handler 决定作答和 Submission 的合法性。录音服务、LLM、ISE、TTS、Worker 不得自行封存 Attempt、补出成绩或决定结束整场。
- **【确定】** `TaskRevision`、发布时选定的 `PaperEntry`、`EvaluationPlan`、提交后的 `Submission`、整场 `CloseManifest`、原始评价证据及正式结果都遵守其各自的不可变边界；不在多个层重复维护同一份题目、答案或成绩。
- **【确定】** `IN_PROGRESS → INPUT_CLOSED → COMPLETED`；`INPUT_CLOSED` 不撤回、不重开。显式重做后旧 A 退出候选，新 B 未正式提交则该题未完成。
- **【确定】** 只有插件声明的必要评价源才执行；必要评价缺失/拒识不是零分。`score_task()` 生成自动单题分，`score_paper()` 初次计算全卷；只复核命中题，覆盖单题总分后仅重新执行 `score_paper()`。
- **【实现建议】** 使用单一应用后端、普通关系型数据库事务和持久作业表即可；不要为领域图中的每个概念都机械建表/基类，也不预设微服务、事件总线或多层抽象。

## 2. 权威身份与引用（不是强制 SQL 表清单）

| 业务身份 | 必须保存/引用的权威信息 | 不应重复保存或推断的内容 |
|---|---|---|
| `TaskIdentity` | `task_id`、`bank_id`、题库内 `task_code`，`UNIQUE(bank_id,task_code)` | 不把相同编号的跨题库题目合并 |
| `TaskRevision` | `task_revision_id`、`task_id`、递增版本、T1.5 内容/图片资源引用、内容指纹 | 不能原地改已创建版本；D 排序号不属内容指纹 |
| `Paper` / `PaperEntry` | 试卷身份、条目位置、选定的 `task_revision_id`、冻结插件/评价合同及所需发布音频引用 | 不根据运行时 `task_code` 再找最新版本；不复制完整题目快照 |
| `PublishedAudio`（或等价资源） | 对应 PaperEntry、语音角色 `guide`/`prompt`、冻结来源文本/合成参数、不可覆盖资源引用 | 不把 E/F 播放音频与 M 参考答案混用 |
| `Session` / `SessionTask` | `session_id`、已发布 `paper_id`、Session 生命周期及复核策略快照；每题唯一 `paper_entry_id` | 不复制第二套 TaskRevision，也不维护独立的三份“完成状态” |
| `Attempt` | `attempt_id`、`session_task_id`、题型自身阶段/断点、`OPEN/SEALED/ABANDONED` | 技术重试不是新 Attempt；不以 ID 最大值认定有效候选 |
| `SessionTask` 当前入口 | 当前 `attempt_id` 的单一指针或等价可验证关系 | 旧已提交 A 是否有效，应看当前候选关系；无须再加一份可失真的 `is_latest` |
| `Playback` / `HelpRequest` / `Turn` | 对应 Attempt、操作身份、完成/失败事实及必要音频、文本引用 | 重播次数/求助次数从有效事实推导，不靠多个可变加减计数器 |
| `Submission` | `submission_id`、所属 SEALED Attempt、正式接受时间、冻结的选择/录音/轮次/重听与求助事实引用 | **儿童选择**可存；**选择题正确答案**只取 TaskRevision.M，不存在第二份 Submission 权威答案 |
| `CloseManifest` | 一次 Session 关闭确认的、有序 `(session_task_id, submission_id)` 集合及输入修订身份 | 不重新复制录音、题干、答案；后续不得改入选集合 |
| `EvaluationJob` / `RawEvaluation` | 固定 `submission_id`、来源合同与版本、输入摘要、状态、结果/错误引用、必要技术重试身份 | 不按 Session 当前题目猜 Submission；不把来源失败改写为合法 0 |
| `AutomaticTaskScore` | 绑定 CloseManifest 输入身份、Submission、插件版本、所消费原始证据 ID 和计算明细 | 不在评分环节修改 RawEvaluation；不使用已被重做替换的旧输入 |
| `AutomaticPaperScore` / `ReviewDecision` | 初次整卷建议分；按命中题、Submission、审核修订保存人工确认或覆盖分 | 不因教师覆盖分再跑 ASR/ISE/LLM/`score_task()` |
| `FinalScoreResult` | 唯一正式成绩源：输入/复核修订、插件版本、全部有效单题分、整卷输出 | 不因页面查询、导出或升级插件重算；首次固化与 Session COMPLETED 原子提交 |

**【实现建议】** `PaperEntry` 可以兼顾草稿与发布条目；冻结音频及 EvaluationPlan 可以采用关联资源或适度结构化字段。`CloseManifest` 可用关系表或能验证每题唯一性的结构表达。哪种 SQL 形态更直接，就用哪种，不为术语对齐强迫一概拆表。

## 3. 五条必须保持原子性的业务事务

**T1｜题库导入确认【已确定原则，建议实现】**：同一事务决定 `(bank_id, task_code)` 的新版本、当前有效版本及 D 展示顺序；预检与提交间检测基线变更。图片可先存为可靠资源引用，但不能发生数据库“只导入半批”的静默状态。A→B→A 仍追加新修订。

**T2｜整题重做【确定】**：仅当 Session=`IN_PROGRESS` 且当前操作无冲突时，原子地使旧 Attempt 退出候选、创建新的 OPEN Attempt，并更新唯一当前指针。旧已 SEALED Submission 保留历史，但不可兜底。与整场关闭的事务必须通过同一权威 Session/SessionTask 行锁或条件更新串行裁决。

**T3｜Submission 正式接受【确定】**：题型 Handler 验证阶段与已保存事实；同一事务固定输入清单、唯一 Submission、`OPEN→SEALED` 和后台可见的持久处理意图。失败不出现“SEALED 无 Submission”或“Worker 已领取半成品”。耗时外部调用必须在事务之外。`submit_request_id` 重传幂等；成功后儿童立即可以进行下一题。

**T4｜结束整场【确定】**：锁定/条件更新 Session，逐题读取**当前**已 SEALED Attempt 的唯一合法 Submission；原子保存 `CloseManifest` + `IN_PROGRESS→INPUT_CLOSED` + 后续处理意图。若 B 重做后未提交，则明确报告该题未完成，整个事务不关闭。`close_request_id` 重传返回同一个结果；关闭后不可撤回或新建 Attempt。

**T5｜复核与正式成绩【确定原则，建议实现】**：复核决定以同一 Submission、输入修订和乐观修订身份提交，防止两个教师相互覆盖；如更改采用分，仅运行同一版本 `score_paper()` 并保存对应预览修订。全部必要评价、自动分和命中复核就绪后，在**同一事务**写入不可变 `FinalScoreResult` 与 Session=`COMPLETED`。无命中复核时可自动完成。

**技术作业领取不是业务长事务【确定原则】**：提交后按 `EvaluationPlan` 建持久工作身份，依赖满足才能领取；CAS/短租约阻止过期 Worker 覆盖。外部服务请求不持有数据库事务。服务商已扣费但本地未落库可能发生，不能承诺物理层“恰好一次调用”。被重做取代且尚未外发的付费作业可跳过。

## 4. 字段消费与配置生效（T1.5 适用）

| 题目字段 | 允许的直接用途 | 必须避免的混淆 |
|---|---|---|
| E 测试员引导语 | 发布时生成可选 `guide` TTS；初次交付 | E 为空不生成语音；主动重听不重复 E |
| F 题目内容 | 发布时生成 `prompt` TTS、儿童题干；Dialogue 完整首问；按需引导/评价上下文 | 不用 M 替代 F，不按问号截断，不用题型显示名称兜底 |
| G 目标对话轮数 | Dialogue Handler 使用冻结正整数 | 不让 LLM 决定轮次，也不写死 2/3 轮 |
| H/I/J 选项图片 | 选择题儿童可见图片与稳定 A/B/C 选项身份 | 不将隐藏说明当选项标签 |
| K 题目图片 | 适用的儿童题目配图、必要评价上下文 | 不和 H/I/J 错列 |
| L 材料说明 | 教师可见场景说明、适用评价/引导上下文 | 不默认作为儿童可见答案提示或 TTS 文本 |
| M 参考答案 | 选择题 A/B/C 权威正确选项；跟读 ISE 朗读目标；开放题适用评价参考 | 绝不用于发布固定 TTS；不下发儿童/高级模式；不把开放题 M 当唯一合法表达 |
| N 评分说明 | 实际需要 LLM 原始评分的通道输入 | 不用于 TTS、动态追问、代码评分插件公式；不会因 N 非空就自动启用 LLM |
| O AI 追问范围 | Speaking/Dialogue 运行时动态引导上下文 | 不直接代替 N，也不让 LLM 结束作答 |

- **【确定】** T1.5 A:O 是唯一现行模板；使用业务字段语义而不是 Excel 列号在服务间传递。旧 19 列及 T1.4 16 列若要迁移，必须按列名和图片锚点显式识别，绝不能静默错列。
- **【确定】** 试卷发布固定 TaskRevision、所选评分插件版本及必要 EvaluationPlan；E/F 固定音频异步准备完成后才能供正常 Session 使用。音频资源不能被覆盖而改变既有 Session 所听内容。
- **【确定】** 动态引导系统级 Prompt 在每次实际操作时读取当前可用配置；不为管理员中途修改设计额外锁定/保护。已保存的动态问题及实际交付事实保持不变，技术恢复不凭空重新生成已保存问题。正式评分 Prompt 和评价合同遵守发布冻结语义。
- **【实现建议／未最终确认】** 可提供发布后手动重生 E/F 固定音频；如果该试卷已经产生 Session，不直接替换其历史固定资源，而通过复制为新草稿重发。此前旧系统有类似入口，但不构成本阶段开发强制要求。

## 5. API 能力与数据可见性，不提前锁死路由名

| 调用侧 | 最小能力 | 输出投影与权限边界 |
|---|---|---|
| 教师题库/组卷 | Excel 预检、确认导入、题目历史、草稿选题、发布/资源准备查询 | 管理接口可按授权读 M/N/O；不把管理 DTO 直接用于儿童接口 |
| 施测小程序作答 | 创建/恢复 Session；读取当前任务；启动/恢复 Attempt；开始/完成播放；提交音频/选项；正式提交；结束整场 | 只给冻结 E/F 及必要 K/H/I/J 资源、当前操作/状态；不下发 M 参考答案、N 评分说明、内部 Prompt、其他儿童资料 |
| 小程序高级模式 | 在本 Session 的合法访问范围内查看已生成的 LLM 问题/引导、真实 ASR、重听/求助事实、经字段筛选的原始评价维度及有限的处理状态/错误摘要；原始维度须明确标为**诊断数据、非正式成绩**。仅在 `FinalScoreResult` 已固化后展示正式单题与整卷成绩明细；按既有 Session 规则允许明确整题重做 | `advanced` 是**UI 模式而非权限凭据**；不提供尚未固化的 `AutomaticTaskScore`、`AutomaticPaperScore` 或教师复核预览；不返回 RawEvaluation 整包、完整模型请求、M/N 或可泄漏参考答案的自由文本解释 |
| 教师诊断/复核 | 按授权访问 Submission 来源级状态、可用证据、选中复核题目、确认或覆盖单题总分、正式结果 | 复核必须属于被冻结的本场输入，保存修订；未固化总分明确为非正式 |
| 普通结果/统计/导出 | 读持久化最终成绩 | 仅 `FinalScoreResult`，不触发评分算法或新外部请求 |

**【实现建议】** 服务端至少验证调用方是否有本 Session/相应教师管理资源的访问资格；不能依靠隐藏控件或请求参数里的 `ui_mode=advanced` 当权限证明。不为此凭空发明复杂角色系统。高级模式可读取的原始评价维度是经筛选的引擎诊断数据，**不等于**评分插件计算的自动单题分、初始整卷分或正式成绩；完整原始载荷、详细内部错误及教师复核数据仅向有权限的教师管理端开放。避免把可能包含答案的模型自由文本解释当作安全诊断字段。

**【实现建议】** API 采用稳定 `request_id/operation_id` 处理创建、提交、重做和关闭等需幂等的写操作；查询返回服务端权威 `allowed_actions` 和阶段投影。路由 URL、HTTP Schema 类名、认证方式在第一批代码里遵循实际客户端和后端选型，不在文档中虚构完整 API 清单。

## 6. 关键异常及对应正确处理

| 场景 | 合同 |
|---|---|
| 播放完成回执重复 | 同 `playback_id` 至多确认一次；只有已完成的主动 USER_REPLAY 计有效重听，首播与技术恢复不算 |
| 网络重进/请求重复 | 查询既有 Session/Attempt、稳定重复操作；不隐式新建、清空录音或追加次数 |
| 音频上传成功但 Submit 失败 | 保留可靠已上传证据，同 Attempt 重试正式提交；未接受前不宣称已完成 |
| ISE 拒识或评分失败 | 不抹除已接受 Submission；IN_PROGRESS 可显式重做，INPUT_CLOSED 后无法重做，本场保持成绩不可用并允许后台技术恢复；不人工伪造分数 |
| ASR 无可信文本 | 与 ASR 技术调用故障分开记录；Dialogue/Speaking 按既有题型专属合同继续或恢复 |
| Worker 迟到结果 | 归属原 Submission，不得提升已被替代的旧 Attempt；不覆盖已固化正式成绩 |
| 调整全局复核比例 | 已创建 Session 用创建时的策略快照；按稳定 SessionTask 身份抽样，模型明确建议复核可独立触发 |
| 提交时关闭整场并发 | 对当前候选和关闭状态作原子裁决，不允许冻结 A 后又同时承认 B 重做成功 |

## 7. 第一批代码的验收顺序【实现建议】

1. **模型与迁移**：实现题库身份/版本和 PaperEntry 引用约束；写出 A→B→A、跨题库相同编号、旧卷不追新版本的数据库测试。
2. **Excel T1.5**：图片 H/I/J/K 锚点、L/M/N/O 字段、M 的选择题 A/B/C 解析；导入/预览/原子提交；不得混入旧列号或错误 TTS 文本来源。
3. **发布与固定资源**：冻结 PaperEntry+插件+EvaluationPlan，E 可空、F 必需、发布语音生成；验证 M 永不被送给固定 TTS。
4. **选择题最小完整业务链**：Session → Attempt → Playback → 选项 Submission → CloseManifest → 用受控测试插件完成双阶段分数 → FinalScoreResult；验证重做 B 未提交不能结算及正式结果原子性。测试插件只是**验证接口的测试实现**，不能替代教师认可的生产评分方案。
5. **延伸到录音和开放题**：接入音频稳定保存、ASR/ISE/LLM 按需评测、Worker 技术恢复、复杂题型 Handler、抽样复核和高级模式诊断。

**反过度设计验收**：不得因为首次测试只覆盖一种题型，就在平台底层添加固定十题、固定五分、固定学段、固定重做次数、固定录音上限或只有一种评分输出维度等限制。

## 8. 仍未确认、但不阻塞最小骨架的事项

1. **普通草稿遇到题库新修订**：建议保留选入草稿时的具体 `task_revision_id`，只提示“题库有新版本”并允许教师主动替换，不静默换题；复制旧卷的完整继承语义已经确定。此项需要业务确认后才在组卷 UI 落实。
2. **物理删除与归档 UI**：未使用的已发布试卷是否提供物理删除、题目归档入口如何展示，仍待确认；不影响不可变引用核心模型。
3. **已发布试卷 TTS 手动重新生成**：原则是历史资源不可覆盖；具体是否开放以及无 Session 时的替换流程，留到发布后台实现阶段确定。
4. **生产评分插件的具体公式**：五题型原始评价合同和双阶段计算边界已确定；实际首个生产插件的分值、扣分、权重、档位需教师确认。不能把旧系统公式、示例测试数值或假算法悄悄宣布为正式评分标准。
5. **正式成绩固化后的特殊更正、下载非正式诊断报告**：第一版不因此重开 Session、覆盖 FinalScoreResult 或提供默认业务入口；真实需要时再单独定义。
6. **已冻结试卷的开放题 ISE**：只有所选插件显式声明且对应类别、参考策略和指标经过供应商验证时才接入；不能基于儿童 ASR 转写自动臆造可靠 ISE 参考。

本文件不取代 T1.5、P1.1、Speaking v1.1、Dialogue v1.0、ST1.0、R1.0、S1.0、E1.0、SW1.1 中更具体的已确认规则。实施者遇到真正矛盾时必须列出证据，不得以“C1.0 比较新”为由擅自覆盖既定业务合同。
