## 0. 约定和关键结论

使用三种标签：**【确定】** 表示本轮已确认的业务要求；**【实现建议】** 表示达成合同的最小技术路径，可以在不改变业务行为的前提下优化；**【跨域待定】** 表示评分、Session 等其他领域必须确定的规则，实施者不得自行补造。

**一句话定义：** Dialogue 是“题目指定目标轮数 + 首轮预设问题 + 后续 LLM 动态追问 + 每轮完整播放、回答、识别与原子推进 + 儿童最后主动提交”的严格串行题型。LLM 不决定轮数，也不决定是否结束。

- 目标轮数 `target_rounds` 是 **Dialogue 题目自身的字段**，随题目版本管理，发布 Paper 时冻结该版本及目标轮数。【确定】
- 不沿用旧系统 2～3 轮硬编码、`round_index IN (0,1,2)` 或基于学段的题型许可白名单。【确定】
- 一轮必须先完整播放问题，才允许录音；儿童点击“结束录音”后，上传、ASR 与下一轮生成**自动串行**进行，没有正常的“下一轮”按钮。【确定】
- ASR 无可信文本不等于服务错误：保存真实空文本及业务语义，向 LLM 提供单独说明，继续目标轮次；正式评分使用原始音频与真实证据。【确定】
- LLM 仅需产生**技术有效的 JSON**，含非空下一轮问题；**不进行语言内容质量在线否决**，包括重复问题、标点数量、字符相似度等。【确定】
- 自动技术重试有预算；耗尽后当前 Attempt **保持 OPEN 且未完成**，不被系统自动废弃、不被计分。儿童模式显示系统错误与“重试当前步骤”；高级模式还显示诊断字段与“整题重做”。【确定】
- 两种模式仅是小程序的**展示外壳**，切换不改变任何后台状态、正在执行的操作、计数或 Attempt。【确定】
- 重播当前已确认问题是独立交互与独立计数；不重新生成问题、不增加轮次。【确定】
- 全部目标轮次完成后才出现“结束本题”，儿童主动提交；Submission 原子接受后立即允许进入下一题，不等待评分。【确定】

## 1. 领域边界与对象

| 对象/能力 | 职责 | 不应承担的职责 |
|---|---|---|
| `TaskBank` / `TaskRevision` | 题库归属、Excel 业务题号、独立内容版本；Dialogue 版本包含 `target_rounds` 与首轮题目等 | 因相同 Excel 题号跨库导入而搬迁旧题 |
| `PaperEntry` | 在 Paper 发布时固定具体 TaskRevision 及算法/资源 | 随题库后来修改而改变已发布内容 |
| `SessionTask` | 当前题目入口、当前有效 Attempt 及候选资格 | 直接运行 Dialogue 轮次推进算法 |
| `Attempt` | 独立作答身份、`OPEN / SEALED / ABANDONED` 生命周期 | 将每次重新上传当作全新 Attempt |
| `DialogueTurn` | 一轮固定问题、问题交付、本轮回答及识别、推进归属 | 同一轮反复更换问题或覆盖正式回答 |
| `AsyncOperation`（或等效操作事实） | ASR、LLM、TTS、播放交付等技术操作的身份、尝试、错误与恢复 | 用技术失败自动废弃 Attempt |
| `Playback` / `Replay` 事实 | 首播和主动重播的身份、结果、独立有效重播统计 | 将重播算成新一轮或 Speaking 求助 |
| `Submission` | 已正式提交且冻结的逐轮问题—回答输入清单与处理身份 | 在后台评分前让未完成 Attempt 自动获得分数 |
| `DialogueHandler` | 当前业务阶段、许可、轮次完整性、推进决策与提交资格 | 让 LLM 自主决定结束或修改已发表 Paper |
| 小程序 `ui_mode` | `child / advanced` 的内容可见性 | 形成新的业务 Attempt、权限角色或服务端状态 |

`Question`、`Answer`、`AdvanceDecision` 可以是 `DialogueTurn` 内的关联事实，不强制各建一张表。此处只定义业务语义，不规定最终 ORM 类和 API 路径。

### 1.1 题目级轮数【确定】

题目创建时教师在 Excel 中设置目标轮数。该字段属于题目版本化内容，而非模型推断值、学段许可或全局隐性默认值。

- 同一个题库中相同业务题号修改轮数或其他题目内容，应产生新的 TaskRevision；已发布旧试卷继续指向旧版本。
- 同一个 Excel 题号可以存在于不同题库中，不应发生静默迁移；业务标识建议 `(bank_id, task_code, version)`，内部稳定引用建议独立主键。
- 目标轮数必须是可执行的正整数，具体由题库 Excel 导入的字段校验实现；**不设置无依据的固定最大轮数**。
- 已发布试卷读取固定 `target_rounds`，Attempt 中途不能受后来题库修改影响。
- `completed_rounds` 指**回答音频已保存且必要 ASR 结果已确认**的轮数，不是当前已创建问题数，也不是模型生成次数。

### 1.2 轮次历史【确定】

首轮问题来自发布试卷的预设题干/引导资源。后续 `Turn(n+1)` 的问题由模型根据完整已确认轮次历史生成。

每个 Turn 绑定一份固定问题文本与可交付音频资源（或待准备的该文本音频），以及对应的当前有效回答。**一旦该轮问题已保存，不得因重试而换成另一个问题。**

## 2. Attempt 生命周期与轮次状态

```text
OPEN ───[儿童完成所有目标轮次并正式提交，事务成功]───> SEALED
  └─────[高级模式手动整题重做，原子替换]───────────> ABANDONED

SEALED ──[Session 仍允许手动重做]──> SEALED + SUPERSEDED（历史提交保留，但不再是当前候选）
```

- 任何一次 ASR / LLM / TTS 失败或自动重试耗尽，**均不触发** `OPEN → ABANDONED`。【确定】
- `RECOVERABLE_ERROR` 是 OPEN Attempt 上当前技术操作的状态或业务阶段投影，**不是**独立 Attempt 终态。【确定】
- 未完成的 OPEN Attempt 不存在可计分的正式 Submission；后台不能拿它的部分录音生成正式成绩。【确定】
- 手动重试当前步骤若最终恢复成功，该 Attempt 继续正常完成并可正式提交；不能将它永久标记为不可计分。【确定】
- 老师选择整题重做后，原 Attempt 与历史记录可审计，但退出当前候选；**不因新 Attempt 未完成而自动回退已被明确放弃的旧作答**。【确定】

### 2.1 单轮可投影阶段【实现建议】

```text
QUESTION_READY → PLAYING_QUESTION → WAITING_ANSWER
                                   → RECORDING_ANSWER → SAVING_ANSWER
                                   → PROCESSING_ASR → TURN_COMPLETED
                                   → (目标未到：GENERATING_QUESTION → 下一轮 QUESTION_READY)
                                   → (目标已到：READY_TO_FINISH)
```

任一需要恢复的处理阶段可叠加“当前操作失败、已停止自动重试”的事实；UI 显示错误，但不改变 Attempt 生命周期。

`SWITCH_UI_MODE` **不是业务事件**。小程序切换显示方式时，当前轮、已录音、已保存 ASR、问题、播放次数和待处理操作全部保持原样。

### 2.2 操作许可矩阵【确定】

| 当前阶段 | 录音/结束录音 | 主动重播问题 | 结束本题 | 重试当前步骤 | 整题重做 | 查询进度 |
|---|---|---|---|---|---|---|
| `QUESTION_READY` / 首播中 | 暂停 | 暂停 | 不允许 | 仅故障时 | 正常流程不开放 | 允许 |
| `WAITING_ANSWER` | 允许录音 | 允许 | 不允许 | 无需 | 高级模式入口 | 允许 |
| `RECORDING_ANSWER` | 允许结束录音 | 暂停 | 不允许 | 无需 | 暂停 | 允许 |
| `SAVING_ANSWER` / `PROCESSING_ASR` | 暂停 | 暂停 | 不允许 | 仅故障时 | 暂停 | 允许 |
| `GENERATING_QUESTION` | 暂停 | 暂停 | 不允许 | 仅故障时 | 暂停 | 允许 |
| `RECOVERABLE_ERROR` | 按可靠断点禁止冲突操作 | 按断点 | 不允许（未完成轮次） | **儿童模式可见** | **高级模式可见** | 允许 |
| `READY_TO_FINISH` | 不再开启新轮 | 不再开启新轮 | **允许** | 无需 | 高级模式入口 | 允许 |
| `SUBMITTING` | 暂停 | 暂停 | 幂等检查 | 失败时按提交合同 | 暂停 | 允许 |
| `SEALED` | 不允许 | 不允许 | 返回已有 Submission | 后台评分另行恢复 | Session 许可下高级模式可见 | 允许 |
| `ABANDONED` | 不允许 | 不允许 | 不允许 | 不允许 | 应操作当前新 Attempt | 历史只读 |

“重播”仅在当前轮初始问题**已完整交付**且还未开始回答录音时允许。不允许首播过程中额外重播；播放期间严格冻结录音及其他冲突事件。

高级模式只是按钮是否可见：系统不能以 `ui_mode=advanced` 来改变任何上述业务阶段判定；手动重做仍须经过原有服务端 Attempt 归属、生命周期和原子串行检查。不增加复杂的新角色授权体系，**但不把隐藏长按当作安全权限保证**。

## 3. 五类可靠断点 Q / P / A / B / T

**断点是已确认的持久化事实，不是必须另外维护的五个枚举列或五张表。** 一道题有多轮，每轮都有自己可恢复的事实边界。

| 断点 | 确认条件 | 发生后续故障时不得丢失的内容 |
|---|---|---|
| **Q：问题确定** | 当前 Turn 的问题身份、文本、来源可靠保存 | 同一问题文本，不能重新询问 LLM 改问题 |
| **P：问题交付** | 当前问题首播完整完成并确认 | 本轮已有回答资格，播放结果 |
| **A：回答保存** | 回答音频 Asset 与 Answer 关联可靠保存 | 本轮原录音、身份、时长、文件校验 |
| **B：识别确认** | 真实 ASR 文本或合法“无可识别内容”结果保存 | 原始 ASR 证据、规范化语义、对应 Answer |
| **T：轮次推进** | 当前轮推进事实与下一轮 Turn 通过同一事务确认 | 当前轮已推进、唯一下一轮问题的固定身份 |

最后一轮完成 B 后，若 `completed_rounds == target_rounds`，直接进入 `READY_TO_FINISH`；**不创建空的下一轮，也不为了凑 T 断点写入虚假问题**。

断点选择必须以某个特定 Turn 和操作为基准；不能用全局 `last_checkpoint='T'` 来代表整道题的全部进度。

## 4. 单轮回答事务：P → A → B

### 4.1 从完整播放到回答录制【确定】

1. 当前 Turn 的问题文本已确认，必要音频已准备成功。
2. 系统完成问题首次完整播放，P 成立，允许儿童录音。
3. 儿童点击“结束录音”，客户端停止本地录音并上传**同一轮回答的稳定身份和音频**；该点击本身不代表 A 已成立，也不能立即跳轮。
4. 服务端可靠保存文件并在事务中确认该 Turn 的唯一正式回答身份，A 成立。
5. A 成立后才触发必要的过程 ASR；结果保存为真实文本或合法空识别语义，B 成立。
6. B 成立后由 Dialogue Handler 自动判断当前是否达到题目固定目标轮数，不要求儿童点击“下一轮”。

同一 Turn **只允许一个正式接受的回答**；网络失败重发同一音频必须复用 `answer_id` 并幂等返回。已经确认 A 的回答不能被“本轮重录”覆盖；教师有意重做时创建全新 Attempt，从第一轮开始。

### 4.2 ASR 的语义合同【确定】

| ASR 结果 | 合法含义 | 本轮后续动作 |
|---|---|---|
| `TRANSCRIBED` | 得到可识别的真实文本 | 保存原文，B 成立，推进 |
| `NO_RECOGNIZED_SPEECH` | 所用接口经已核实映射明确表示无法识别可信语音/内容 | 保存空文本和原因，B 成立，推进 |
| `LOW_CONFIDENCE` | 有低置信度证据 | 依据真实厂商响应规范确定是否可作为无可信文本，不得乱映射 |
| `PROVIDER_ERROR` | 网络、超时、供应商服务或鉴权故障 | 保留 A，执行有限技术重试；不能冒充儿童沉默 |

**“儿童没有说话／本轮没有可信 ASR”只能作为传递给追问 LLM 的独立上下文说明**；实际 `asr_text` 保持真实空值/空文本，保留原始响应及规范化类别。

Dialogue **不设置最低累计录音时长，也不要求每轮达到 Speaking 的最低时长**。但必须有实际接收并能解码的合法音频，不能把损坏文件或零字节上传伪装成有效回答。即使儿童一直沉默，只要技术上完成录音和 ASR 语义确认，也能按既定目标轮数推进；后续根据试卷固定的评分算法据实评分。【确定】

## 5. 轮次推进原子事务：B(n) → T(n) / Q(n+1)

### 5.1 进入下一轮的唯一前提【确定】

- Attempt 仍是当前有效 `OPEN` 作答。
- 当前轮问题 P、回答 A、必要 ASR B 均成立。
- `completed_rounds < target_rounds`。
- 当前无另一个已被接受的推进结果或冲突操作。

如果 `completed_rounds == target_rounds`，不再请求 LLM，进入 `READY_TO_FINISH`；不存在 `should_end` 及其控制路径。

### 5.2 推进事务流程【确定 + 实现建议】

1. 在短事务内登记稳定的 `advance_operation_id`，绑定 `attempt_id`、当前 `turn_id`、已经确认的问答历史输入边界和固定题目版本；提交事务。
2. **数据库事务之外**调用 LLM 生成下一轮问题；必要时按自动技术重试政策再次生成，同一轮绝不并行推进。
3. 最低技术校验：响应可解析为 JSON 对象，必要 `next_question` 存在且为非空字符串；不要求 `should_end`，也不强制 `reason_code`。可交付给 TTS 的必要技术条件仍须满足。
4. 校验通过后进入短数据库事务，再次确认 Attempt、当前 Turn、操作身份、固定输入进度、目标轮数和并发条件。
5. **同一事务**：创建唯一 `Turn(n+1)` + 标记 `Turn(n)` 已推进，绑定原 `advance_operation_id`；二者一起提交或一起回滚。
6. 提交成功后形成 T 和下一轮 Q，再调用 TTS 准备并完整播放下一问。**已经保存 Q 的问题不因 TTS 失败而再次调用 LLM 生成不同问题**。
7. 事务响应丢失或被重试时先查询已有推进结果，返回原 `Turn(n+1)`；不得新建另一轮或覆盖原问题。

建议约束 `UNIQUE(attempt_id, round_index)`，并对推进操作身份建立相应幂等关系；不要求使用额外分布式事件平台或把 LLM 调用包进数据库事务。

### 5.3 LLM 最小技术校验，明确取消运行时质量门槛【确定】

推荐合同（示意）：

```json
{
  "next_question": "你平时和小猫一起做什么？"
}
```

- **必须**：有效 JSON 结构、需要的字段、非空且可交付的问题文本；外部调用正常完成。
- **不做在线质量否决**：是否与以前问题重复、是否只能有一个问号、固定文字数量、是否足够“聪明”、是否语义新颖，以及机械相似度判定。
- **不再使用**：旧版“重复问题 → 反复生成 → 质量例外放行”这类引发阻塞的机制。
- 问题质量通过提示词和上线前模型对照测试改进；运行时不能因主观质量分数阻断孩子完成合法轮次。
- 内容安全处理与“语言质量打分”是不同问题；不得把普通语言质量判断伪装成必过安全规则，也不得形成无上限自动生成循环。

### 5.4 技术自动重试耗尽时的行为【确定】

LLM 无效 JSON、供应商错误等技术问题先执行**可配置且有上限的自动重试**。耗尽后：

- 停止当前自动重试链，记录操作错误及最后可靠 B 断点。
- **Attempt 仍为 OPEN、未完成，不能提交、不能计分，也不自动废弃。**
- 儿童模式显示简单“系统错误”，并开放**“重试当前步骤”**；高级模式额外显示可诊断字段和**“整题重做”**。
- 点击“重试当前步骤”是新的**显式恢复触发**，在相同业务轮次和同一逻辑推进目标上开启一轮**有边界的技术尝试**。不要求儿童重录上一轮回答，不创建新 Attempt，不跳轮。
- 手动重试再次失败后，仍可继续手动发起，不设人为总次数上限；**每次自动尝试仍有自己的有限预算**，页面刷新本身不得偷偷重置并连续自动调用。
- 失败时后台如仍有迟到结果，必须通过持久化操作身份/执行代次或等效事务条件拒绝覆盖已确认的新推进结果；一个 Turn 最多只有一次实际生效的下一轮创建。
- 如教师判断本次过程已经无法可靠完成，使用高级模式的“整题重做”显式废弃旧 Attempt 并原子创建新的 Attempt。

**重要语义区分：** 技术故障导致 Attempt 暂时无法计分 ≠ 永久失去有效提交资格。手动恢复成功并完成所有目标轮次后，仍可正常正式提交。

## 6. 问题播放、重新播放和独立计数

### 6.1 首次交付【确定】

当前 Q 的问题播放必须完整完成，才能成立 P 并开放录音。首播失败则保持 Q，按相应音频操作断点恢复/提示错误；不重新生成已固定的问题，不允许越过首播直接录音。

### 6.2 儿童主动重播【确定】

- 仅在 `WAITING_ANSWER`、当前轮初次问题已经成功交付且还未开始回答录音时提供“重新播放”按钮。
- 播放当前 Turn 已保存的问题文本对应的**原音频**；不重新调用 LLM、不生成新 Turn、不改写问题文本。
- 重播期间暂停录音、结束本题及其他冲突操作；播放结束后恢复原 `WAITING_ANSWER`。
- 每次被接受且成功完整交付的主动重播，记录一个独立有效 `Replay` 事实；失败、重复回执和网络重传不重复计数。
- 首播、自动动态追问的首次播放都不计为重播。

建议：

```text
replay_count = COUNT(当前 Attempt 中已成功交付、由儿童主动触发的重播事实)
```

**不**将 `replay_count` 与 Speaking 的 `help_count` 或 Dialogue 的 `completed_rounds` 混在一起。是否扣分及每次扣多少，必须由 Paper 发布时冻结的单题转换评分算法指定；本专项只保存真实计数事实。【跨域待定：具体评分公式】

## 7. 纯 UI 的“儿童模式 / 高级模式”

- `child` 和 `advanced` 只是小程序展示模式，可通过题型标题隐藏长按切换；**不持久化为 Attempt 的业务阶段**。【确定】
- 切换前后：同一个 Attempt、同一个当前 Turn、相同问题/录音/ASR/播放/计数及正在执行的异步操作；不发起新业务请求、不重新生成、不清空状态。【确定】
- 儿童模式仅展示正常录音、重播、正常提交；在故障时额外展示简洁系统错误及“重试当前步骤”。
- 高级模式额外展示内部诊断字段和“整题重做”；正常串行限制仍有效，不能边生成问题边绕过事务创建另一个当前 Attempt。
- 当前设计**不新增角色体系或复杂身份权限认证**；模式切换不构成服务器授予权力的证明。服务端照常核验 SessionTask/Attempt 归属、生命周期与互斥操作，避免串行规则失效。
- 调试信息不得展示服务商 API 密钥、私有 `.env` 或不必要的敏感数据。

该双模式原则同步适用于 Speaking，但不要求 Speaking 和 Dialogue 合并题型状态机。

## 8. 断点恢复与故障矩阵

| 故障 | 保留的已确认事实 | 恢复路径 | 是否自动废弃 Attempt |
|---|---|---|---|
| 当前问题已保存但 TTS 失败 | Q、问题原文 | 在同一问题上恢复 TTS/交付 | 否 |
| 初次问题播放失败 | Q | 提示/重试当前播放步骤，不开始回答 | 否 |
| 问题交付后儿童尚未录音 | P | 返回同一轮等待回答，可主动重播 | 否 |
| 回答已保存但 ASR 服务故障 | A、原音频 | 有限技术重试或显式重试本段 ASR | 否 |
| ASR 明确无可识别文本 | B、真实空识别及来源 | 作为本轮有效分析，自动推进 | 否 |
| LLM 返回非法 JSON、缺必需问题文本 | B、推进操作身份、错误 | 有限自动重试；耗尽后开放手动重试 | 否 |
| LLM 问题重复、标点奇怪但技术有效 | 已确认返回的可用文本 | **直接接受，不因内容质量阻断** | 否 |
| 下一轮数据库事务失败 | B、操作身份；可能已存在 T | 查询是否已有 Turn(n+1)，再恢复原操作 | 否 |
| 下一轮问题 Q 已保存但播放失败 | T + Q | 恢复这条问题的交付 | 否 |
| 主动重播失败 | 原 P 与重播失败事实 | 解除本次重播占用，不增加有效次数 | 否 |
| 客户端退出或切换界面模式 | 所有服务端已确认事实 | 查询当前 Attempt/Turn 与 allowed_actions | 否 |
| 高级模式明确点击整题重做 | 旧 Attempt 历史完整保留 | 原子 `ABANDONED`/`SUPERSEDED` + 新 Attempt | **是，且必须显式触发** |
| 已提交后后台评分失败 | 原 Submission 固定输入 | 恢复同一 Submission 的异步评分 | 否 |

恢复依据是**服务端已确认事实和操作身份**，不是客户端缓存的 `loading`、当前页内存或自称“第几轮”。技术自动重试耗尽后必须结束占用，不能把页面永久锁死。

## 9. 提交本题与异步评分

### 9.1 提交条件【确定】

- 当前有效 Attempt 为 `OPEN`，所属 SessionTask 仍允许作答。
- `completed_rounds == target_rounds`，每轮 P/A/B 均已确认。
- 无仍未完成的冲突操作；不得用“已生成问题数”代替“已完成回答轮数”。
- 儿童明确点击“结束本题”，而不是 LLM `should_end` 或最后一轮 ASR 结果自动提交。
- **不要求最低累计录音时长**，不另设内容充分性门槛。

### 9.2 原子提交事务【确定】

在一个数据库事务内：

1. 复核当前 Attempt、SessionTask、固定目标轮数、完成轮次、全部必要输入已可靠保存及串行许可。
2. 冻结 Submission manifest：**每一轮唯一 Turn、问题原文/版本、回答音频 Asset、ASR 证据关联、必要交付事实**，以及有效独立 `replay_count` 计数依据。
3. 原子创建唯一正式 Submission、后台处理身份并将 Attempt 封存为 `SEALED`。
4. 事务提交成功后返回“提交成功”；允许立即进入下一题，后台按固定 manifest 异步评分。任何外部 ASR/ISE/LLM 评分调用不得放进封存数据库事务。

提交幂等：同一 `finish_request_id` 重传返回既有 Submission；不同请求竞争也不得创建多个有效 Submission。事务失败时不出现半提交。后台不能领取尚未完整固定输入的提交。

### 9.3 整题重做与候选资格【确定】

- 由高级模式中的显式“整题重做”触发，整个 Attempt 从第一轮重新开始；不支持只重录 Turn(n)。
- 若旧 Attempt 未提交，旧 `OPEN → ABANDONED`；若已 `SEALED`，保留历史提交，标记已被新 Attempt 替代，不改写旧提交事实。
- 旧模型、ASR、评分异步迟到结果不能修改当前新 Attempt 或变成当前候选成绩。
- 已被明确放弃的旧作答不可因为新 Attempt 未完成而悄悄恢复作为有效计分候选。
- **【跨域待定】** Session 已请求最终结算但尚未结算完成时能否重做，交由 Session 专项规定；已正式结算后不得通过重做改写正式结果。

## 10. 推荐事件合同

| 事件 | 必要前置 | 成功的持久化变化 |
|---|---|---|
| `START_ATTEMPT` | SessionTask 可开始；目标题目版本已固定 | Attempt + 首轮 Q |
| `QUESTION_DELIVERED` | 当前 Q，完整首播确认 | P，开放录音 |
| `REPLAY_CURRENT_PROMPT` | 当前 P 已成立、仍在等待本轮回答 | 创建独立重播操作，播放期冻结冲突动作 |
| `REPLAY_COMPLETED` | 有效重播 ID，完整播放完成 | 该次重播计为有效一次，恢复原阶段 |
| `STOP_RECORDING` | 当前正在录音 | 发起当前轮录音结束与上传，不直接跳轮 |
| `ANSWER_SAVED` | 当前 P，合法音频和稳定回答身份 | A，不覆盖已有正式回答 |
| `ASR_COMPLETED` | 对应 Answer 与技术操作有效 | B，真实文本或无可信内容语义 |
| `ADVANCE_TURN` | B 完成且未达到目标轮数 | 创建/恢复唯一自动推进操作 |
| `NEXT_QUESTION_READY` | 技术有效 LLM 结果 | 原子创建下一轮 Q 并标记当前轮 T |
| `TECHNICAL_RECOVERY_EXHAUSTED` | 有界技术重试耗尽 | 保留断点和 OPEN，结束占用，提示错误 |
| `RETRY_CURRENT_STEP` | 真实技术失败已停止自动尝试 | 显式开始同一步新的一轮有限技术执行；不创建新轮/Attempt |
| `REQUEST_FINISH` | 目标轮数已全部完成且无冲突操作 | 进入原子正式提交校验 |
| `SUBMISSION_ACCEPTED` | 提交事务成功 | manifest 固定、Submission 创建、Attempt SEALED |
| `RESTART_ATTEMPT` | 当前业务允许重做、用户明确触发、无未完成冲突事务 | 原子废弃/替代旧 Attempt + 新 Attempt |
| `RESUME_ATTEMPT` | 已有 Attempt | 服务端事实重建阶段和可用动作；不新建作答 |

事件名称为建议命名，不限定实际 REST API 数量、事件总线框架或持久化表数。

## 11. 初版必测验收合同

### A. 题目、轮次与正常流程

1. 题目版本的 `target_rounds` 发布后冻结；题库后来修改不影响旧 Paper。
2. 不硬编码旧 2～3 轮或学段白名单；不同题目可以配置不同目标轮数。
3. 首轮来自预设题目，后续由 LLM 基于已确认完整历史生成。
4. 未完成首播禁止录音；首播成功才允许回答。
5. 结束录音后自动上传、ASR、推进，不要求人工点击“下一轮”。
6. 创建下一轮 Q 不等于完成该轮回答；只有 B 成立才增加 `completed_rounds`。
7. 达到目标轮数后不继续调用 LLM；只显示“结束本题”，不自动 Submission。
8. 不校验 Dialogue 最低累计录音时长；仍核验技术上合法的音频文件。

### B. ASR、LLM 结果语义

9. ASR 确认无可识别内容时保存真实空文本，视为完成本轮必要识别并自动推进。
10. 提示词中可说明“儿童没有说话／无可信 ASR”，但实际原始 `asr_text` 不出现该注入说明。
11. ASR 技术错误保留原回答音频，不伪装成沉默且不跳轮。
12. LLM 返回与前轮重复的问题，只要技术有效就接受并交付。
13. LLM 返回多个问号或不符合旧句式模板的问题，不因质量校验拒绝。
14. LLM 返回无效 JSON / 缺 `next_question` / 空问题，执行有限技术重试。
15. LLM 输出不含 `should_end`，不能决定对话结束，也不参与正式提交。
16. LLM 问题 Q 已保存而 TTS 失败时，恢复交付 Q，不重新生成新问题。

### C. 原子性与幂等

17. 回答音频已存而确认回包丢失，同一 `answer_id` 重传返回原结果，不生成第二回答。
18. 同轮另一个不同回答身份不能悄悄覆盖已正式接收的 Answer。
19. 并发推进请求最多创建一个 `Turn(n+1)`。
20. 保存“本轮已推进”和创建下一轮 Q 同事务成功或一起回滚。
21. LLM 迟到结果不覆盖已经保存的下一轮问题，也不污染新 Attempt。
22. 切换 UI 模式不修改任何当前轮或业务事实。
23. 提交 manifest、Submission 和 Attempt `SEALED` 在同一原子事务完成。
24. 提交成功允许立即进入下一题，不等待正式评分。
25. 正式提交重复请求最多形成一个 Submission。

### D. 重播、恢复与人工重做

26. 只有当前问题首次交付且未录音时可主动重播。
27. 重播不调用 LLM、不新增 Turn、不覆盖问题文本。
28. 两次独立完整重播记两次有效 `replay_count`；重复回执/失败播放不重复计数。
29. 重播期间录音按钮不可用，服务端拒绝并发操作。
30. 自动 LLM 重试耗尽时 Attempt 仍 `OPEN`，不能正式提交或计分，也不自动废弃。
31. 儿童模式可见系统错误及“重试当前步骤”，无需进入高级模式。
32. 每次手动重试有独立有限自动尝试预算；再次失败仍停止，不能无限后台自激活。
33. 手动重试成功恢复原推进位置，不重新录音、不新建 Attempt，最后可正常评分。
34. 高级模式额外显示诊断字段和“整题重做”，仅改变显示，不改变当前状态。
35. 老师明确整题重做时原子创建新 Attempt；旧未提交 Attempt `ABANDONED`，已提交旧 Attempt 历史保留但退出候选。
36. 旧 Attempt 被明确废弃后，所有迟到外部操作不能影响新的当前作答。
37. 新 Attempt 最终未提交时，不回退已经被明确放弃的旧候选成绩。
38. 出错停在中间状态的 OPEN Attempt 不会被后台作为已提交有效输入偷跑正式评分。
39. 客户端退出再进入，只依据服务端断点恢复，不自动丢弃/重建整个 Attempt。
40. 已提交 Submission 后的正式评分失败恢复同一 Submission，不强制儿童重做。

## 12. 与其他专项设计的协同事项

- **Speaking v1.1**：重播计数、只读重播资源、纯 UI 模式、公共 Submission 事务等一致；**不合并两种题型的业务 Handler**。
- **题库版本化 / Excel 导入**：采用 `(bank_id, task_code, version)` 唯一业务身份、内部稳定引用；Excel 为题目内容创建修改的唯一入口。题目目标轮数纳入 TaskRevision；Paper 发布固定引用。跨库同号独立，不静默迁移。【公共题库专项】
- **ASR 适配**：所有“无可信 ASR”与技术错误必须依据实际供应商代码和响应字段严格映射；当前文档不杜撰厂商错误码。【公共音频专项】
- **评分**：保留每轮问题—回答、空识别、真实音频和独立重播次数；是否对沉默、重播扣多少分由发布时绑定的单题转换评分算法决定，本文件不硬编码公式。【评分专项】
- **Session**：整卷结算及结算过程中重做的边界由 Session 决定；已正式结算不允许改写成绩。【Session 专项】
- **模型适配**：保证 JSON/非空文本技术校验、有限重试与可追溯失败；**不重新引入语言重复、问号数量、最大字符数等在线质量硬门槛**。【公共 LLM 专项】
- **实施技术细节**：数据库表拆分、队列、音频 Asset、JSON schema、具体 API、超时/技术重试次数，可在实施设计中明确；不得增加未经确认的儿童作答次数上限或整题自动作废规则。

---

**初版设计完成标准**：实现者可以依据本文构建确定性测试覆盖完整问答循环、Q/P/A/B/T 断点、LLM 技术有效性、严格串行、手动恢复、重播和 Submission；不得用旧系统隐性业务限制填补尚未决定的跨领域事项。正式开发前应同步核对上位架构、Speaking v1.1 与 TaskRevision 的术语及关系。
