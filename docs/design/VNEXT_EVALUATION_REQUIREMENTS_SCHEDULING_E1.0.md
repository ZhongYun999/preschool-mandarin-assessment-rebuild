# VNext｜评分插件评测依赖声明与按需调度 E1.0

> 设计讨论补充稿。日期：2026-11-12。状态：业务方向已确认，接口形式为实施建议；不是已实施代码。与 T1.5／P1.1／R1.0／S1.0 配套使用。旧系统仅供审计参考。

## 1. 为什么需要本补充

VNext 已确定：题型 Handler 产生可靠 Submission；LLM、ISE、本地声学等适配器保存 RawEvaluation；试卷绑定的评分插件先运行 `score_task()` 将需要的原始评价转为单题系统分，再运行 `score_paper()` 得到初始整卷成绩；教师可覆盖某题采用分，随后只重跑 `score_paper()`，正式结果固化于数据库。现在需要解决：**后台如何知道某一插件对某一题型是否真正需要 ISE，避免无意义付费调用？**

原则：**未被当前试卷冻结插件声明使用的评价来源，绝不因为题型属于开放题而默认调用。** 评测来源是否需要，取决于试卷所选插件的版本化需求声明，不取决于前端页面、不依赖后台全局“打开 ISE”的布尔开关。

## 2. 三种责任、两项接口

1. **ScoringPlugin 的声明部分**：声明各题型需要的 `RawEvaluation` 来源、合同版本和必要粒度；无外部服务调用或副作用。
2. **EvaluationOrchestrator／Adapter**：根据试卷冻结的需求计划调度 ASR／LLM／本地分析／ISE，验证和持久化结果；不调用 `score_task()` 进行折算。
3. **ScoringPlugin 的计算部分**：`score_task()` 只读已存在的原始评分与作答事实，输出系统单题转换分；`score_paper()` 只读确定的单题采用分，输出整卷汇总、总分、档位，可在教师复核修改后重复调用。

注：ASR 是多数 LLM 文本评价的上游输入依赖，**不是 ISE**；虽然可以在调度计划中作为先决步骤，不代表它必须伪装成一个 `RawEvaluation` 数值分数。选择题的选择和正确答案是 Submission + TaskRevision 事实，也不需要伪装成 ISE/LLM 原始评分。

## 3. 建议的最小插件声明

```python
class ContentScoringV1:
    plugin_id = "content_scoring_v1"
    implementation_version = "1.0.0"

    evaluation_requirements = {
        "instruction": (),  # 仅消费已确认选择事实
        "repetition": ("iflytek_ise:repetition_v1",),
        "qa": ("llm_text:qa_v1", "local_acoustic:qa_v1"),
        "dialogue": ("llm_text:dialogue_v1", "local_acoustic:dialogue_turns_v1"),
        "speaking": ("llm_text:speaking_v1", "local_acoustic:speaking_v1"),
    }

    def score_task(self, task_context, raw_evaluations, submission_facts): ...
    def score_paper(self, paper_context, effective_task_scores): ...
```

此处的键值是**示意性源码接口**，不是固定业务白名单。`iflytek_ise:repetition_v1` 表示某个已在服务端实现、已验证的评测合同，不能只凭服务名称认定该接口可用于任意开放题。未来新增评分插件 B 可在 `qa`／`dialogue`／`speaking` 的声明里增加相应 ISE 合同，**不必改这三个题型的作答状态机**。上述 `*_v1` 是举例命名，并非声称现已有新合同部署。

**默认策略：只调度明确声明的来源。** 不在列表里的 ISE 不排队、不发网络请求、不收费。若日后确有“能取得则利用、失败则按固定替代算法计算”的需求，再为某插件显式定义 best-effort 依赖和失败分支；**不能把所有可能有用的付费评价默认列为可选并尝试调用**。

## 4. 需求与题目冻结

1. 创建或修改草稿时按已选插件预览其评价来源（例如教师可看到“说话题：LLM＋本地声学，不调用讯飞 ISE”）。无需教师填写来源参数。
2. **试卷发布时**，冻结 `plugin_id + implementation_version`、每道试卷题目使用的评价合同版本、所需评价来源及必要的引擎请求策略。`PaperEntry` 仍固定 `TaskRevision`；这些是试卷执行合同的一部分。
3. 历史试卷复制为新草稿时，按已经确认的“整卷原样复制”语义，继承当时的题目修订与评分插件身份／评价需求；不自动追赶题库最新版本或最新插件。若原插件或评价合同已无法执行，必须显式报告，不得暗中替换。
4. 已发布试卷的 Session 只能使用其冻结计划，不读取某个新部署插件的最新默认依赖来更改评测范围或增加 ISE 调用。

可在发布事务中将冻结依赖解析为 `EvaluationPlan` 或等价不可变数据；无须额外创建教师可编辑的复杂配置表。

## 5. 按需调度时序

1. 客户端提交并获得服务端已确认的 Submission；对于 Speaking／Dialogue，只有达到各自规定的封存条件才能进入相应正式评价。
2. 调度器读取该 `SessionTask` 对应的冻结 `EvaluationPlan`；根据题型、合同版本及必要的 ASR 前置依赖生成具体任务。
3. 只为**需要且尚无合格结果**的来源创建任务。开放题未声明 ISE 时，不能因为通用录音 Worker 路径、普通话规范“旁路”或重试扫描而自动触发 ISE。
4. 适配器返回时保存按来源区分的 `RawEvaluation`，包含真实指标、单位、版本、状态、原始响应引用及必要的错误原因。对来源数据做合同验证，不在此处计算五分制、求助／重听扣分或整卷分。
5. **所有当前插件要求的证据**已准备且合法时，运行 `score_task()`；所有单题系统转换分就绪后，执行一次 `score_paper()` 形成初始整卷成绩。
6. 教师复核某题的系统转换分时，只形成覆盖记录和新的有效单题分；仅再次运行同版 `score_paper()`。不重新发出 LLM、ASR、ISE 或 `score_task()` 请求。
7. 对儿童和一般正式结果页面只展示数据库已固化的最终结果；中途未完成或失败时只显示“成绩生成中／成绩暂不可用”，内部诊断可显示 N/A 与原因。

## 6. ISE 对开放题的特殊要求

保留开放题 ISE 适配能力 **不意味着** 已批准“用儿童 ASR 转写作为 ISE 参考文本”的所有场景。必须为将来真正使用 ISE 的插件单独明确：

- 每个题型采用哪种 ISE 能力与类别，该类别是否实际支持开放表达；
- 评测参考文本的来源、可信度限制及其版本化策略；
- 对话题是逐轮评分还是整体评分（以及音频和逐轮参考怎样配对）；
- 供应商实际返回哪些字段，插件必需哪些字段；必要字段未返回的失败行为；
- 按具体评测合同完成验证后才能被插件声明引用并用于正式评分。

这些约束是针对“插件宣称需要一个现有接口实际上不能提供的指标”进行兼容性检查，不把业务算法硬限制为固定分数规则。

## 7. 成本控制、幂等和失败处理

- **无声明不调用**：开放题默认可使用 LLM 与本地声学，插件没要求 ISE 就绝不创建其任务。
- **无效重复不调用**：同一冻结 Submission、同一已验证评价合同／参考策略，已存在成功 `RawEvaluation` 则直接复用，不为页面刷新或 Worker 重启再次付费。
- **失败重试不重复计分**：评测失败与真实 0 分严格区分；重试针对缺失／失败来源，保持可追踪执行记录和幂等键。不能无边界重复自动重试昂贵服务；具体重试策略在 Worker 设计中确定。
- **必要来源失败则不固化完整成绩**：未返回该合同要求的指标时保持 `FAILED/INVALID`，教师和诊断端显示 N/A；正式儿童端不给半成品分数。
- **性能与额度可观测**：按插件 ID、题型、来源、合同版本记录请求次数、完成状态和可取得的用量数据，方便核对 ISE 额度去向。不得因记录用量而保存密钥或敏感凭据。
- **跨试卷不盲目复用**：只有输入音频、参考文本、评价合同、提示词、版本与许可条件等完整身份一致才讨论安全复用；默认以当前 Submission 为幂等边界。

## 8. 必须补到既有专项文档的部分

| 既有文档 | 必须补充／修改 |
|---|---|
| P1.1：组卷发布 | 发布时冻结插件的评价来源需求／合同版本；复制旧卷时连同执行需求原样复制；组卷预览可提示预期的付费来源 |
| R1.0：RawEvaluation | 来源是否创建由冻结 EvaluationPlan 决定；未被要求的来源“没有记录”是正常，不是评分缺失；必要来源缺失／失败才阻断 |
| S1.0：双阶段评分 | 插件接口增加只读需求声明；`score_task()` 等待自身需要的原始证据；复核后只执行 `score_paper()` |
| 后续 Session／Worker 设计 | 作答封存后按计划调度；幂等、失败重试、任务去重、供应商额度统计、避免不需要的 ISE 旁路 |
| 后续管理端／小程序审计 | 无最终固化分不得向儿童泄露中间成绩；教师可看诊断；不能由页面逻辑决定启用 ISE |

## 9. 针对性验收案例

1. 插件 A 的 QA、Dialogue、Speaking 未声明 ISE：完成三种题型后，**ISE 调用总数为 0**；ASR、LLM 和本地声学按要求完成。
2. 插件 B 声明 QA 的 ISE 合同：只有满足该合同的 QA 会调用 ISE；不能顺带为其它题型发起请求。
3. 同一题型不同试卷绑定不同插件：评价来源严格跟随各自已发布的试卷，不受后端默认插件变化影响。
4. 已发布试卷更换服务器程序：不自动采用新版本插件的额外 ISE 需求。
5. 只有已经持久化的成功 ISE 评价时：Worker 重启或用户重开页面不产生重复收费请求。
6. ISE 返回拒绝、未返回该合同必需字段或适配器返回非法结构：不得伪造零分或正式成绩。
7. 教师修改某题复核分：只重算 `score_paper()`，ISE／LLM／ASR 调用计数不变，`score_task()` 不重跑。
8. 复制旧试卷：题目修订、评分插件和来源需求原样保留；历史任务与成绩不复制。
9. 未使用 ISE 的正式结果可在不存在任何 ISE `RawEvaluation` 的情况下正常完成，不误判数据残缺。
10. 对话题需 ISE 但参考文本策略尚未经验证：发布预检明确提示不兼容，不擅自调用“ASR 回填 ISE”。

## 10. 当前建议定稿范围

本轮确定 **声明所需来源 → 发布冻结 → 后台按需调用 → 保存原始评价 → 双阶段评分 → 复核后仅重算整卷** 的执行架构。开放题 ISE 的具体评分协议、参考策略和专业适用性，等真实评分插件需要时单独验证；当前默认不为未使用 ISE 的插件执行该接口。不新增教师字段或在线配置面板。
